### 1.1.1 path_utils.py — 路径安全工具

```
函数 safe_resolve(base_path: str, user_path: str) -> Path | None
    输入:
        - base_path: 白名单基路径（如 /home/ubuntu/gitee-software）
        - user_path: 用户传入的路径字符串
    处理步骤:
        1. 将 user_path 用 Path(user_path).resolve() 解析为绝对路径
        2. 获取 base_path 的 resolved 版本 Path(base_path).resolve()
        3. 尝试用 relative_to() 判断解析后的路径是否在 base_path 下
        4. 如果不在白名单内 → 返回 None（拒绝）
        5. 如果在白名单内 → 返回 Path 对象
    输出:
        - 成功: Path 对象
        - 失败: None（由调用方返回 403）
    异常处理:
        - ValueError: relative_to 抛出 → 路径穿越 → 返回 None
        - PermissionError: 无权限访问路径 → 返回 None
        - OSError: 路径过长或非法字符 → 返回 None

函数 is_within_base(target_path: str, base_path: str) -> bool
    输入:
        - target_path: 待校验的路径
        - base_path: 基路径
    处理步骤:
        1. 调用 safe_resolve(base_path, target_path)
        2. 返回结果是否为 None
    输出:
        - True: 路径安全
        - False: 路径穿越或无效

函数 get_repo_path(repo_name: str) -> str | None
    输入:
        - repo_name: "workspace" | "skills-library" | "projects" | "all"
    处理步骤:
        1. 从全局配置中获取三库基路径映射
        2. 如果 repo_name == "all": 返回三个基路径的列表
        3. 否则: 返回对应仓库的基路径
        4. 如果仓库名不存在 → 返回 None
    输出:
        - 成功: 路径字符串或路径列表
        - 失败: None
    异常处理:
        - KeyError: 仓库名映射不存在 → 返回 None
```

### 1.1.2 cmd_utils.py — 系统命令工具

```
函数 run_cmd(command: str, timeout: int = 5) -> Dict
    输入:
        - command: 要执行的 shell 命令字符串
        - timeout: 超时秒数（默认 5s）
    处理步骤:
        1. 用 asyncio.create_subprocess_shell 创建子进程
        2. 设置 timeout 超时
        3. 等待子进程完成，读取 stdout 和 stderr
        4. 如果超时 → 终止子进程 → 抛出超时异常
        5. 返回 { "returncode": int, "stdout": str, "stderr": str }
    输出:
        - 成功: 命令执行结果字典
        - 超时: 抛出 CommandTimeoutError
    异常处理:
        - asyncio.TimeoutError: 命令执行超时 → 强制 kill 子进程 → 抛出异常
        - FileNotFoundError: 命令不存在 → 返回 returncode=-1, stderr="command not found"
        - PermissionError: 无执行权限 → 返回 returncode=-1, stderr="permission denied"

函数 run_systemctl(action: str, service_name: str) -> Dict
    输入:
        - action: "is-active" | "status" | "show"
        - service_name: "hermes-gateway" | "sw-dashboard"
    处理步骤:
        1. 根据 action 构建 systemctl 命令
        2. 调用 run_cmd(f"systemctl {action} {service_name}", timeout=5)
        3. 解析 stdout 提取关键信息
        4. 返回解析后的字典
    输出:
        - is-active: { "status": "active" | "inactive" | "failed" | "unknown" }
        - status: { "status", "uptime", "pid", "memory" }
    异常处理:
        - CommandTimeoutError: 超时 → 返回降级数据 { "status": "unknown" }
        - 命令返回非零: 返回 { "status": "inactive" } （服务可能未安装）

函数 run_crontab(action: str, command: str = None, enable: bool = True) -> Dict
    输入:
        - action: "list" | "toggle"
        - command: 要启停的 cron 命令（toggle 模式需要）
        - enable: True=启用, False=禁用（toggle 模式需要）
    处理步骤:
        1. action == "list":
            a. 执行 "crontab -l"
            b. 逐行解析 crontab 表达式
            c. 提取 schedule / command / comment / enabled（以 # 注释行=禁用）
            d. 返回 CronJob 列表
        2. action == "toggle":
            a. 执行 "crontab -l" 获取当前全部 crontab 内容
            b. 根据 command 匹配对应行
            c. 如果 enable=True → 去除行首的 "#" 注释
            d. 如果 enable=False → 在行首添加 "#" 注释
            e. 将修改后的全部内容写入 crontab（echo "... " | crontab -）
            f. 返回操作结果
    输出:
        - list: CronJob 列表
        - toggle: { "success": bool, "message": str }
    异常处理:
        - 无 crontab: "crontab -l" 返回空 → 返回空列表
        - toggle 未匹配行: 返回 { "success": false, "message": "未找到匹配的任务" }
        - 写入 crontab 失败: 返回 { "success": false, "message": str(e) }
```

### 1.1.3 date_utils.py — 日期时间工具

```
函数 format_timestamp(timestamp: float | str | None, fmt: str = "ISO8601") -> str
    输入:
        - timestamp: 时间戳（浮点数秒数 / ISO 字符串 / None）
        - fmt: 输出格式（默认 ISO8601）
    处理步骤:
        1. 如果 timestamp 是 None → 返回空字符串
        2. 如果 timestamp 是数字（float/int）→ 用 datetime.fromtimestamp() 转换
        3. 如果 timestamp 是字符串 → 尝试解析为 ISO 格式
        4. 格式化为 "2026-06-03T14:30:00+08:00" 格式
        5. 返回格式化后的字符串
    输出:
        - 成功: ISO 8601 格式时间字符串
        - 输入无效: 空字符串
    异常处理:
        - ValueError: 时间戳格式无法解析 → 返回空字符串
        - OSError: 时区信息不可用 → 使用 UTC 兜底

函数 parse_uptime(seconds: float | str) -> str
    输入:
        - seconds: 秒数（浮点数）
    处理步骤:
        1. 将秒数转换为天/小时/分钟
        2. 格式化为 "X 天, X 小时, X 分钟"（中文友好）
        3. 如果 < 1 小时 → 显示 "X 分钟"
        4. 如果 < 1 天 → 显示 "X 小时, X 分钟"
    输出:
        - 人类可读的运行时长字符串
    异常处理:
        - TypeError: 输入不是数字 → 返回 "未知"
        - ValueError: 负数 → 返回 "未知"
```

## 1.2 服务层

### 1.2.1 file_service.py — 文件系统服务

```
函数 build_tree(base_path: str, sub_path: str = "/", max_depth: int = 5, current_depth: int = 0) -> List[FileNode]
    输入:
        - base_path: 仓库基路径
        - sub_path: 子路径（用于懒加载）
        - max_depth: 最大递归深度
        - current_depth: 当前递归深度
    处理步骤:
        1. 组合完整路径: full_path = base_path + sub_path
        2. 用 safe_resolve(base_path, full_path) 校验路径安全
        3. 如果校验失败 → 返回空列表
        4. 如果 current_depth > max_depth → 返回空列表（截断）
        5. 遍历 full_path 下的所有条目（os.scandir 或 pathlib.iterdir）
        6. 对每个条目:
            a. 跳过隐藏文件/目录（以 . 开头）
            b. 如果是文件:
                - 获取 size, mtime
                - 创建 FileNode(type="file", isLeaf=True)
            c. 如果是目录:
                - 递归调用 build_tree(sub_path=子目录, current_depth+1)
                - 创建 FileNode(type="directory", isLeaf=False, children=递归结果)
        7. 按 name 排序返回（目录在前，文件在后）
    输出:
        - 成功: FileNode 列表
        - 路径无效: 空列表
    异常处理:
        - PermissionError: 无权限读取目录 → 跳过该目录
        - FileNotFoundError: 目录不存在 → 返回空列表
        - OSError: 读取异常 → 跳过异常条目

函数 read_file(file_path: str) -> FileContent
    输入:
        - file_path: 文件绝对路径
    处理步骤:
        1. 校验路径安全（safe_resolve）
        2. 检查文件是否存在 → 不存在返回 404
        3. 检查文件大小是否超过 10MB → 超过返回 413
        4. 用 aiofiles.open(mode='r', encoding='utf-8', errors='replace') 异步读取
        5. 获取文件 size, mtime
        6. 调用 detect_language() 检测语法类型
        7. 调用 is_editable() 判断是否可编辑
        8. 返回 FileContent
    输出:
        - 成功: FileContent { path, name, content, size, mtime, language, editable }
        - 文件不存在: 抛出 FileNotFoundError
        - 文件过大: 抛出 FileTooLargeError
    异常处理:
        - FileNotFoundError: 文件不存在 → HTTP 404
        - FileTooLargeError: 文件超过 10MB → HTTP 413
        - UnicodeDecodeError: 编码错误 → errors='replace' 自动降级
        - PermissionError: 无权限读取 → HTTP 403

函数 write_with_backup(file_path: str, content: str, create_backup: bool = True) -> FileWriteResponse
    输入:
        - file_path: 文件绝对路径
        - content: 新的文件内容字符串
        - create_backup: 是否创建 .bak 备份
    处理步骤:
        1. 校验路径安全（safe_resolve）
        2. 校验文件后缀在白名单内（is_editable）
        3. 如果 create_backup == True:
            a. 备份路径 = file_path + ".bak"
            b. 用 shutil.copy2(file_path, backup_path) 复制文件（保留元数据）
        4. 用 aiofiles.open(mode='w', encoding='utf-8') 写入新内容
        5. 获取写入后的文件大小
        6. 返回 FileWriteResponse { path, size, backup_path, timestamp }
    输出:
        - 成功: FileWriteResponse
        - 不可编辑: 抛出 PermissionError
        - 写入失败: 抛出 WriteError（保留 .bak 备份）
    异常处理:
        - PathTraversalError: 路径穿越 → HTTP 403
        - PermissionError: 不可编辑（二进制或白名单外）→ HTTP 403
        - OSError: 写入失败（磁盘满/权限）→ 保留 .bak 备份 → HTTP 500
        - FileNotFoundError: 原文件不存在 → 创建新文件（不做备份）

函数 detect_language(file_path: str) -> str
    输入:
        - file_path: 文件路径
    处理步骤:
        1. 获取文件扩展名
        2. 扩展名映射表:
            - .py → "python"
            - .js/.ts → "javascript"
            - .yaml/.yml → "yaml"
            - .md → "markdown"
            - .json → "json"
            - .env → "env"
            - .toml → "toml"
            - .sh → "shell"
            - .log → "text"
            - 其他 → "text"
        3. 返回映射后的语言名称
    输出:
        - 语言名称字符串
    异常处理:
        - 无扩展名: 返回 "text"

函数 is_editable(file_path: str) -> bool
    输入:
        - file_path: 文件路径
    处理步骤:
        1. 获取文件扩展名
        2. 检查是否在白名单内: [".py", ".js", ".ts", ".yaml", ".yml", ".md",
           ".json", ".env", ".toml", ".sh", ".txt", ".cfg", ".conf", ".ini", ".csv"]
        3. 检查是否为二进制文件（可选：读取前几个字节检测 null byte）
        4. 如果后缀在白名单内且非二进制 → 返回 True
        5. 否则返回 False
    输出:
        - True: 可编辑
        - False: 只读
    异常处理:
        - 路径不存在: 返回 False（安全起见）
```

### 1.2.2 config_service.py — 配置管理服务

```
函数 read_config(config_name: str) -> ConfigFile
    输入:
        - config_name: "config.yaml" | ".env" | "CLAUDE.md" | "SOUL.md"
    处理步骤:
        1. 从配置映射表获取配置文件路径:
            - config.yaml → ~/.hermes/config.yaml
            - .env → ~/.hermes/.env
            - CLAUDE.md → ~/.hermes/CLAUDE.md
            - SOUL.md → ~/.hermes/SOUL.md
        2. 校验路径安全
        3. 读取文件内容（aiofiles）
        4. 检测语言类型
        5. 返回 ConfigFile { name, path, content, language, editable=true, last_modified }
    输出:
        - 成功: ConfigFile
        - 配置名无效: 抛出 ValueError
    异常处理:
        - FileNotFoundError: 配置文件不存在 → 返回默认空内容（config.yaml 可返回默认模板）
        - PermissionError: 无权限 → HTTP 403
        - ValueError: 配置名不在白名单内 → HTTP 400

函数 read_env(masked: bool = True) -> ConfigFile
    输入:
        - masked: 是否掩码敏感信息（默认 True）
    处理步骤:
        1. 读取 ~/.hermes/.env 文件内容
        2. 如果 masked == True:
            a. 调用 mask_secrets(content) 生成掩码版本
            b. content = 掩码版本
            c. original_content = None（不暴露原始值）
        3. 如果 masked == False:
            a. content = 原始内容
            b. original_content = None
        4. 返回 ConfigFile { content, original_content, language="env" }
    输出:
        - ConfigFile（带/不带掩码）
    异常处理:
        - FileNotFoundError: .env 不存在 → 返回空内容
        - 同 read_config 异常

函数 write_config(config_name: str, content: str, validate: bool = True, create_backup: bool = True) -> FileWriteResponse
    输入:
        - config_name: 配置文件名
        - content: 新内容
        - validate: 是否校验格式
        - create_backup: 是否创建备份
    处理步骤:
        1. 从映射表获取配置文件路径
        2. 校验路径安全
        3. 如果 validate == True:
            a. 如果 config_name 是 YAML 文件（config.yaml）:
                - 尝试 yaml.safe_load(content)
                - 如果解析失败 → 抛出 YAMLError（返回具体错误行）
            b. 如果 config_name == ".env":
                - 校验格式: 每行应为 KEY=VALUE 或注释或空行
                - 如果有无效行 → 抛出 ValueError
        4. 如果 create_backup → 调用 write_with_backup(path, content, True)
        5. 如果 validate == False → 直接写入（带备份）
        6. 返回 FileWriteResponse
    输出:
        - 成功: FileWriteResponse
        - YAML 格式错误: 抛出 YAMLError（HTTP 400）
    异常处理:
        - yaml.YAMLError: 格式错误 → HTTP 400，detail 包含错误位置
        - 其他同 write_with_backup

函数 mask_secrets(content: str) -> str
    输入:
        - content: 原始 .env 内容
    处理步骤:
        1. 逐行解析 .env 内容
        2. 对每行，用正则匹配敏感 Key:
            - 匹配模式: (API_KEY|TOKEN|SECRET|PASSWORD|PRIVATE_KEY|ACCESS_KEY) 等（大小写不敏感）
            - 格式: KEY=VALUE
        3. 如果匹配到敏感 Key:
            a. VALUE 部分长度 >= 8:
                - 保留前4位 + "****" + 保留后4位
                - 示例: "sk-abcdefghijklmnop" → "sk-a******nop"
            b. VALUE 部分长度 < 8:
                - 全部替换为 "****"
        4. 如果未匹配到敏感 Key → 保留原行
        5. 返回掩码后的完整内容
    输出:
        - 掩码后的文件内容字符串
    异常处理:
        - 输入为空: 返回空字符串
        - 编码异常: 用 errors='replace' 处理（理论上不会发生）

函数 read_markdown(md_name: str) -> ConfigFile
    输入:
        - md_name: "CLAUDE.md" | "SOUL.md"
    处理步骤:
        1. 从映射表获取路径
        2. 校验路径安全
        3. 读取文件内容
        4. 返回 ConfigFile { language="markdown" }
    输出:
        - ConfigFile (markdown 类型)
    异常处理:
        - 同 read_config

函数 list_crontab() -> List[CronJob]
    输入: 无
    处理步骤:
        1. 调用 cmd_utils.run_crontab(action="list")
        2. 对每行 crontab:
            a. 跳过空行和纯注释行（整行以 # 开头且不含命令部分）
            b. 解析 5 段 cron 表达式 + 命令
            c. 如果行以 # 开头但包含命令 → enabled=False
            d. 尝试从系统日志（/var/log/syslog 或 journalctl）查找 last_run
            e. 构建 CronJob { raw, schedule, command, comment, enabled, last_run, last_output }
        3. 返回 CronJob 列表
    输出:
        - CronJob 列表（可能为空）
    异常处理:
        - crontab -l 执行失败（cron 未安装）→ 返回空列表
        - 解析某行失败 → 跳过该行，记录 warning

函数 toggle_cron(command: str, enable: bool) -> CronToggleResponse
    输入:
        - command: 要启停的 cron 命令全文
        - enable: True=启用, False=禁用
    处理步骤:
        1. 调用 cmd_utils.run_crontab(action="toggle", command=command, enable=enable)
        2. 返回 CronToggleResponse { success, message }
    输出:
        - 操作结果
    异常处理:
        - 未匹配行: 返回 { success=false, message="未找到匹配的 cron 任务" }
        - 写入失败: 返回 { success=false, message=str(e) }
```

### 1.2.3 log_service.py — 日志服务

```
函数 list_log_files(log_dir: str) -> LogFileListResponse
    输入:
        - log_dir: 日志目录路径
    处理步骤:
        1. 校验 log_dir 路径安全
        2. 用 pathlib.Path(log_dir).glob("*") 列出所有文件
        3. 过滤出 .log 文件和 .gz 归档文件
        4. 对每个文件获取 name, path, size, mtime
        5. 按 mtime 降序排序（最新的排最前）
        6. 识别 default_file: 默认名 "hermes.log"，如存在则标记
        7. 返回 LogFileListResponse { files, log_path, default_file }
    输出:
        - 日志文件列表
    异常处理:
        - FileNotFoundError: 日志目录不存在 → 返回空列表 + 告警
        - PermissionError: 无权限 → 返回空列表

函数 tail_log(file_path: str, num_lines: int = 100) -> LogContent
    输入:
        - file_path: 日志文件绝对路径
        - num_lines: 返回行数（默认 100，限制 ≤2000）
    处理步骤:
        1. 校验路径安全
        2. 检查文件存在
        3. 获取文件总大小
        4. 反向读取算法（优化大文件）:
            a. 从文件末尾开始，用 aiofiles 读取大小为 4096 字节的块
            b. 累加已读行数，直到 >= num_lines 或到达文件开头
            c. 将读取的块用 '\n' 分割，取最后 num_lines 行
            d. 如果文件非常大（>100MB），最多读取 2MB 尾部数据
        5. 组装 LogContent { file, content, lines, total_size, truncated }
        6. truncated = True 表示文件过大只返回了尾部数据
    输出:
        - 日志尾部内容
    异常处理:
        - FileNotFoundError: 日志文件不存在 → HTTP 404
        - UnicodeDecodeError: 编码异常 → errors='replace' 降级
        - FileTooLargeError: 文件 > 100MB → 只读取尾部 2MB → 标记 truncated=true

函数 search_logs(keyword: str, file_path: str, max_lines: int = 50, case_sensitive: bool = False, context_lines: int = 0) -> LogSearchResult
    输入:
        - keyword: 搜索关键字
        - file_path: 日志文件路径
        - max_lines: 最大返回行数（默认 50，限制 ≤500）
        - case_sensitive: 是否大小写敏感
        - context_lines: 匹配行前后各返回 N 行（默认 0）
    处理步骤:
        1. 校验路径安全
        2. 检查文件存在
        3. 打开文件，逐行读取
        4. 对每行进行关键字匹配:
            a. case_sensitive=True: keyword in line
            b. case_sensitive=False: keyword.lower() in line.lower()
        5. 如果匹配:
            a. 添加匹配行到 matches 列表
            b. 如果 context_lines > 0: 添加前 N 行（如果存在）和后 N 行
        6. 如果 matches 数量 >= max_lines → 停止搜索，标记 truncated=True
        7. 记录搜索耗时
        8. 返回 LogSearchResult { keyword, file, total_matches, matches, truncated, time_cost_ms }
    输出:
        - 搜索结果
    异常处理:
        - FileNotFoundError: 日志文件不存在 → HTTP 404
        - UnicodeDecodeError: 编码异常 → errors='replace' 降级
        - MemoryError: 文件过大 → 限制搜索范围（前 500MB）
        - TimeoutError: 搜索超过 10s → 返回已匹配结果 + truncated=true

函数 list_archives(log_dir: str) -> List[LogArchive]
    输入:
        - log_dir: 日志目录路径
    处理步骤:
        1. 列出 log_dir 下所有 .log.* 和 .gz 文件
        2. 过滤条件: 文件名包含 "hermes.log." 或匹配归档模式
        3. 对每个归档文件获取 name, path, size, mtime
        4. 按 mtime 降序排序
        5. 返回 LogArchive 列表
    输出:
        - 归档文件列表（可能为空）
    异常处理:
        - 目录不存在: 返回空列表
        - 无归档文件: 返回空列表
```

### 1.2.4 dashboard_service.py — 仪表盘聚合服务

```
函数 get_gateway_status() -> GatewayStatus
    输入: 无
    处理步骤:
        1. 调用 run_systemctl("is-active", "hermes-gateway")
        2. 如果 status == "active":
            a. 调用 run_systemctl("show", "hermes-gateway") 获取详细信息
            b. 从 systemd show 输出解析: MainPID, MemoryCurrent(需转换MB), CPUUsageNS
            c. 从 systemd status 输出解析 Uptime
        3. 如果 status == "inactive" / "failed":
            a. 返回降级数据，部分字段为 None
        4. 组装 GatewayStatus { status, uptime, pid, memory_mb, cpu_percent }
        5. 如果任何字段获取失败 → 默认值 None
    输出:
        - GatewayStatus
    异常处理:
        - CommandTimeoutError: systemctl 超时 → 返回 { status: "unknown" }
        - 服务未安装: → 返回 { status: "unknown" }
        - 部分字段解析失败: 该字段设为 None（降级）

函数 get_session_stats() -> SessionStats
    输入: 无
    处理步骤:
        1. 读取 Gateway 的状态文件或日志（Path: ~/.hermes/hermes-gateway/var/stats/sessions.json）
        2. 如果文件不存在 → 返回默认 SessionStats（全为 0）
        3. 解析 JSON:
            - total_sessions: 今日总会话数
            - total_messages: 今日总消息数
            - active_sessions: 当前活跃会话
            - avg_duration_sec: 平均会话时长（秒）
        4. 如果解析失败 → 返回默认值
        5. 返回 SessionStats
    输出:
        - 会话统计（文件不存在时返回默认值）
    异常处理:
        - FileNotFoundError: 状态文件不存在 → 返回默认值（全 0）
        - json.JSONDecodeError: 文件格式错误 → 返回默认值
        - PermissionError: 无权限 → 返回默认值

函数 get_pipeline_status() -> PipelineProgress | None
    输入: 无
    处理步骤:
        1. 读取项目根目录的 .project-meta.yaml 文件
        2. 如果文件不存在 → 返回 None
        3. 解析 YAML:
            - total_stages: 总阶段数（通常 8）
            - stages: 阶段列表，每个包含 id, name, status, progress
        4. 计算 current_stage: 找到第一个 status != "completed" 的阶段
        5. 计算 overall_progress: 所有阶段 progress 的平均值
        6. 返回 PipelineProgress { current_stage, total_stages, stages, overall_progress }
    输出:
        - PipelineProgress（文件不存在时返回 None）
    异常处理:
        - FileNotFoundError: .project-meta.yaml 不存在 → 返回 None
        - yaml.YAMLError: 格式错误 → 返回 None
        - KeyError: 缺少关键字段 → 返回 None（降级友好）

函数 get_cron_status() -> List[CronJobStatus]
    输入: 无
    处理步骤:
        1. 调用 config_service.list_crontab()
        2. 对每个 cron 任务，提取任务名称（从 comment 或 command 中截取）
        3. 如果任务名称为空 → 自动命名为 "Cron Job N"
        4. 映射到 CronJobStatus { name, schedule, last_run, last_status, enabled }
    输出:
        - Cron 任务执行状态列表
    异常处理:
        - crontab 执行失败 → 返回空列表

函数 aggregate_dashboard() -> DashboardData
    输入: 无
    处理步骤:
        1. 并行调用（asyncio.gather）:
            - get_gateway_status()
            - get_session_stats()
            - get_pipeline_status()
            - get_cron_status()
        2. 如果有任何调用超时或失败 → 使用降级数据
        3. 获取服务器当前时间
        4. 组装 DashboardData { gateway, sessions, pipeline, cron_jobs, server_time, version }
        5. 返回 DashboardData
    输出:
        - 仪表盘聚合数据
    异常处理:
        - 单个服务故障: 对应字段使用降级数据，不影响其他字段
        - 所有服务故障: 返回全部为默认值的 DashboardData
        - asyncio.TimeoutError: 单个协程超时 → 结果设为 None，其他正常返回
```

```
        2. 如果 token 存在 → 添加 Header: X-Token = token
        3. 继续请求

    响应拦截器:
        1. 如果响应状态码为 2xx → 直接返回 response.data
        2. 如果响应状态码为 401:
            a. 清除 localStorage 中的 token
            b. 使用 ElMessage.error("Token 已失效，请重新登录")
            c. 跳转到 /login 页面
        3. 其他错误:
            a. 从 error.response.data.detail 提取错误信息
            b. 使用 ElMessage.error(错误信息)
            c. 返回 Promise.reject(error)

    导出: api 实例
```
