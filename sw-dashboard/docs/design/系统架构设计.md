## 1. 架构总览

翠花集群管理面板采用 **前后端分离的单体应用** 架构。后端提供 RESTful API 并托管前端静态文件，前端通过 axios 与后端通信。整个系统运行在旧云服务器上，通过 Tailscale 内网访问。

```
┌─────────────────────────────────────────────────────────┐
│              公子的 ThinkPad (浏览器)                     │
│         Tailscale 100.x.x.x → 旧云服务器 :8900           │
└──────────────┬──────────────────────────────────────────┘
               │
               │ HTTPS (Tailscale MagicDNS)
               ▼
┌─────────────────────────────────────────────────────────┐
│               sw-dashboard (旧云服务器)                    │
│                                                          │
│  ┌──────────────┐    ┌──────────────────────────────┐   │
│  │   Vue SPA    │◄──►│        FastAPI Backend        │   │
│  │  (Static)    │    │  ┌─────┐ ┌──────┐ ┌───────┐ │   │
│  │              │    │  │Router│→│Service│→│Models │ │   │
│  │  dist/       │    │  └─────┘ └──────┘ └───────┘ │   │
│  └──────────────┘    └───────────┬──────────────────┘   │
│                                  │                      │
│         ┌────────────────────────┼──────────────┐       │
│         │                        │              │       │
│         ▼                        ▼              ▼       │
│  ┌────────────┐   ┌────────────────┐   ┌────────────┐  │
│  │ 文件系统    │   │ Gateway API    │   │ 系统命令    │  │
│  │ (三库+日志) │   │ (systemctl)    │   │ (crontab)  │  │
│  └────────────┘   └────────────────┘   └────────────┘  │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

## 2. 分层架构

系统划分为 **4 层**，每层职责明确，依赖关系单向：

### 2.1 展示层 (Presentation Layer)

| 组件 | 说明 |
|:-----|:------|
| **Vue 3 SPA** | 基于 Vue 3 Composition API 的单页应用 |
| **Element Plus** | UI 组件库，提供 Layout、表单、表格、树等 |
| **vue-router** | 前端路由，5 个页面（仪表盘/存储/配置/日志/技能） |
| **Pinia** | 状态管理，Token 和全局配置 |
| **vue-codemirror** | CodeMirror 6 编辑器封装，用于配置编辑 |
| **axios** | HTTP 客户端，统一管理 Token 注入和错误处理 |

### 2.2 路由层 (Router Layer)

| 模块 | 路由前缀 | 职责 |
|:-----|:---------|:------|
| `routers/dashboard.py` | `/api` | 仪表盘数据聚合、健康检查 |
| `routers/storage.py` | `/api` | 文件系统浏览、读写 |
| `routers/configs.py` | `/api` | 配置文件管理、Cron 管理 |
| `routers/logs.py` | `/api` | 日志 tail、搜索、归档 |
| 静态文件托管 | `/` | Vue SPA 的 `dist/` 目录 |

### 2.3 服务层 (Service Layer)

| 服务 | 职责 |
|:-----|:------|
| `dashboard_service.py` | 聚合 Gateway 状态、Pipeline 进度、Cron 状态 |
| `file_service.py` | 目录树生成、文件读写、备份、路径安全校验 |
| `config_service.py` | YAML/.env/MD 解析、Key 掩码、Crontab 管理 |
| `log_service.py` | 日志 tail（反向读取）、关键字搜索、归档列表 |

### 2.4 基础设施层 (Infrastructure Layer)

| 组件 | 职责 |
|:-----|:------|
| **文件系统** | 三库（workspace/skills-library/projects）+ 日志文件 |
| **systemd** | 管理 Gateway 和 Dashboard 服务 |
| **crontab** | 定时任务调度 |
| **Tailscale** | 内网安全通信 |

## 4. 数据流

### 4.1 请求生命周期

```
浏览器输入 URL
    │
    ▼
Vue Router 解析 → 显示 Layout
    │
    ├── 页面加载 → 组件 mounted
    │       │
    │       ▼
    │   Pinia Store (状态)
    │       │
    │       ▼
    │   API Module (axios)
    │       │ 添加 X-Token Header
    │       ▼
    │   FastAPI Router
    │       │ Depends(verify_token)
    │       ▼
    │   Service Layer
    │       │ 业务逻辑
    │       ▼
    │   Infrastructure (文件系统/systemd/crontab)
    │
    └── 响应返回 → 组件渲染
```

### 4.2 日志轮询流

```
Logs.vue mounted
    │
    ├── setInterval(3000ms)
    │       │
    │       ▼
    │   axios.get('/api/logs/tail?lines=200')
    │       │
    │       ▼
    │   logService.tail()
    │       │ 文件尾部反向读取 → 返回最近 N 行
    │       ▼
    │   更新 logContent ref → 模板自动渲染
    │
    └── onUnmounted → clearInterval
```

### 4.3 文件编辑流

```
用户点击"编辑"按钮
    │
    ├── 进入编辑模式 (readonly = false)
    │
    ├── 用户在 CodeMirror 中修改
    │
    ├── 点击"保存"
    │   ├── 显示二次确认弹窗 (ElMessageBox.confirm)
    │   │
    │   └── 确认 → PUT /api/storage/file
    │           │
    │           ▼
    │       file_service.write_with_backup()
    │           │
    │           ├── shutil.copy2 → .bak 备份
    │           │
    │           └── aiofiles.open → 写入新内容
    │
    └── 成功提示 / 失败提示
```

## 6. 安全架构

| 安全维度 | 措施 |
|:---------|:------|
| **网络隔离** | Tailscale 内网 + iptables 白名单（仅 100.64.0.0/10） |
| **认证** | 简单 Token（X-Token Header），Tailscale 二次保障 |
| **路径穿越** | `Path(path).resolve()` 后校验 `is_relative_to(BASE)` |
| **文件类型** | 仅允许文本文件编辑（白名单后缀） |
| **编辑备份** | 写前自动 `.bak` 备份 |
| **输入校验** | Pydantic v2 Schema 校验所有请求体 |
| **大文件保护** | 文件读取上限 10MB，编辑上限 1MB |

## 8. 异常处理策略

| 异常场景 | 处理方式 | HTTP 状态码 |
|:---------|:---------|:-----------|
| Token 无效 | 返回错误提示，跳转登录 | 401 |
| 文件不存在 | 显示 404 提示 | 404 |
| 路径穿越攻击 | 拒绝请求，记录日志 | 403 |
| 写入失败 | 保留 .bak 备份，提示用户 | 500 |
| YAML 格式错误 | 显示具体错误位置 | 400 |
| 大文件读取 | 提示文件过大，拒绝读取 | 413 |
| 编码错误 | errors='replace' 兜底 | 200（内容可能部分乱码） |
| 系统命令超时 | 超时 5s，返回降级数据 | 200（部分数据可用） |

## 9. 性能优化

| 优化项 | 方案 | 预期效果 |
|:-------|:-----|:---------|
| 目录树加载 | 懒加载模式（按需展开） | 首次加载 < 500ms |
| 日志查看 | 反向读取（只读尾部 N 行） | 大文件 < 100ms |
| 前端体积 | CodeMirror 按需加载语言包 | 首屏 JS < 200KB |
| API 响应 | 内网延迟 < 5ms | 响应 < 50ms |
| 并发控制 | Uvicorn --workers 1 | 内存占用 < 200MB |
| 静态资源 | Vite 构建压缩 + gzip | 资源加载 < 1s |

## 10. 架构决策记录 (ADR)

| ID | 决策 | 理由 | 替代方案 |
|:---|:-----|:-----|:---------|
| ADR-001 | 前后端分离单体 | 部署简单，一进程托管所有 | 分离部署（Nginx + 后端） |
| ADR-002 | REST API 轮询日志 | 实现简单，内网延迟低 | WebSocket（复杂度过高） |
| ADR-003 | Token 认证 | Tailscale 已隔离，Token 二次保障 | OAuth（过度设计） |
| ADR-004 | pathlib 递归目录树 | 零外部依赖，API 现代 | scandir（编码复杂） |
| ADR-005 | CodeMirror 6 | 轻量（1MB vs Monaco 5MB） | Monaco（体积过大） |
| ADR-006 | systemd 直接启动 | 零依赖，Linux 标准 | Docker（资源开销） |
