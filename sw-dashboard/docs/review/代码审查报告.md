## P0 — 阻塞问题（必须退回）

### P0-1 🔴 `file_service.read_file()` 路径穿越漏洞（安全漏洞）

**文件**: `backend/services/file_service.py:138-142`

**问题描述**：`read_file()` 的路径安全校验存在严重漏洞。当路径不在任何安全路径白名单内时，代码使用 `safe_resolve("/", file_path)` 作为 fallback，而 `"/"` 作为 base_path 会使任意绝对路径通过校验。

```python
matched_base = is_within_any_safe_path(file_path)
if matched_base is None:
    resolved = safe_resolve("/", file_path)  # ← 漏洞："/" 匹配所有路径
    if resolved is None:
        raise PathTraversalError(f"路径不在安全白名单内: {file_path}")
```

`safe_resolve("/", "/etc/passwd")` 中 `Path("/etc/passwd").relative_to(Path("/"))` 永远合法，因此可以通过 **任意文件路径** 调用 `read_file()` 读取服务器上任何文件。

**风险等级**：P0 — 严重安全漏洞，可导致任意文件读取（信息泄露）

**修复建议**：删除 `safe_resolve("/", ...)` fallback，改为直接抛 `PathTraversalError`：

```python
matched_base = is_within_any_safe_path(file_path)
if matched_base is None:
    raise PathTraversalError(f"路径不在安全白名单内: {file_path}")
```

### P0-2 🔴 配置基路径 `_HERMES_HOME` 与设计文档不一致（设计偏差）

**文件**: `backend/config.py:31`

**问题描述**：设计文档（系统架构设计.md、API设计.md）中 `hermes` 基路径定义为 `~/.hermes`，配置文件的路径期望为：
- `~/.hermes/config.yaml`
- `~/.hermes/.env`

但实际代码将 `_HERMES_HOME` 设为 `~/.hermes/profiles/software-dev`：

```python
_HERMES_HOME: str = "~/.hermes/profiles/software-dev"
```

这导致所有配置文件的路径变为：
- `~/.hermes/profiles/software-dev/config.yaml`
- `~/.hermes/profiles/software-dev/.env`

与 API 设计文档中示例的路径（`/home/ubuntu/.hermes/config.yaml`）不一致。

**影响**：用户按文档期望访问的配置文件路径与代码实际路径不符，可能导致"配置文件不存在"或误修改错误配置文件。

**修复建议**：
- 确认目标环境：如果 production 路径确实是 `~/.hermes/profiles/software-dev/`，则更新设计文档
- 或者将 `_HERMES_HOME` 改为 `~/.hermes` 以匹配设计文档

### P0-3 🔴 前端 404 路由错误指向登录页（核心逻辑错误）

**文件**: `frontend/src/router/index.ts:47-51`

**问题描述**：404 通配路由 `/:pathMatch(.*)*` 的 `component` 指向了 `Login.vue`，而非 404 占位组件。

```typescript
{
  path: '/:pathMatch(.*)*',
  name: 'NotFound',
  component: () => import('@/views/Login.vue'),  // ← 错误：应使用 404 组件
  meta: { title: '404' }
}
```

这意味着访问任何不存在路由（如 `/nonexistent`）会直接显示登录页，而非 404 错误提示。

**影响**：导航到非法 URL 时不显示 404 错误页，误导用户认为需要重新登录。

**修复建议**：创建独立的 404 页面组件或使用 `el-result` 占位：

```typescript
component: () => import('@/views/NotFound.vue')
```

### P0-4 🔴 设计文档中 `ApiResponse` 的 `error` 字段被替换为 `message`（设计偏差）

**文件**:
- 设计文档: `数据模型设计.md`
- 实际代码: `backend/models/schemas.py:17-21`

**问题描述**：数据模型设计文档规定的 `ApiResponse` 模型包含 `error: Optional[str] = None` 字段，但实际实现替换为 `message: str = ""`。

**设计文档**：
```python
class ApiResponse(BaseModel, Generic[T]):
    success: bool = True
    data: Optional[T] = None
    error: Optional[str] = None  # ← 设计使用 error
```

**实际代码**：
```python
class ApiResponse(BaseModel, Generic[T]):
    success: bool = True
    data: Optional[T] = None
    message: str = ""  # ← 实际使用 message
```

**影响**：泛型 `T` 的用法正确，但错误字段命名与设计不一致。前端未依赖此字段，功能无影响，但属于设计偏差。

**修复建议**：统一为 `error: Optional[str] = None` 或更新设计文档。
