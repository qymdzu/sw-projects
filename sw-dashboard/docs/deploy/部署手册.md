## 1. 环境要求

### 1.1 服务器要求

| 项目 | 最低配置 | 推荐配置 |
|------|----------|----------|
| CPU  | 1 核     | 2 核     |
| 内存 | 256MB    | 512MB    |
| 磁盘 | 1GB      | 5GB      |
| 系统 | Ubuntu 22.04+ / Debian 12+ | Ubuntu 22.04+ |

> 本方案针对 **512MB 内存的旧云服务器** 优化，采用 systemd 直接启动方式，
> 避免 Docker 带来的额外内存开销。

### 1.2 软件依赖

| 软件 | 最低版本 | 说明 |
|------|----------|------|
| Python | 3.12+ | 后端运行环境（推荐 3.12） |
| Node.js | 18+ | 前端构建环境（仅首次部署需要） |
| npm | 9+ | Node 包管理器（随 Node.js 安装） |
| systemd | 247+ | 服务管理（Ubuntu 22.04 内置） |

### 1.3 安装系统依赖

```bash
# Ubuntu / Debian
sudo apt update
sudo apt install -y python3 python3-venv python3-pip nodejs npm curl

# 确认版本
python3 --version   # 需要 3.12+
node --version      # 需要 v18+
npm --version       # 需要 9+
```

## 2. 快速启动

### 2.1 一键部署（推荐）

```bash
# 进入项目目录
cd ~/gitee-software/sw-projects/sw-dashboard

# 设置 Token（务必修改为强密码）
export HERMES_DASHBOARD_TOKEN="your-strong-token-here"

# 执行一键部署脚本
bash scripts/deploy.sh
```

脚本会自动完成：
1. ✅ 环境检查（Python、Node.js、systemd）
2. ✅ 创建 Python 虚拟环境并安装依赖
3. ✅ 安装 npm 依赖并构建前端
4. ✅ 配置 systemd 服务
5. ✅ 启动服务并执行健康检查

### 2.2 分步部署

如果一键部署失败，或需要手动控制，可按以下步骤操作：

#### Step 1: 安装后端依赖

```bash
cd ~/gitee-software/sw-projects/sw-dashboard

# 创建虚拟环境
python3 -m venv venv

# 安装依赖
source venv/bin/activate
pip install --upgrade pip setuptools wheel
pip install -r backend/requirements.txt
deactivate
```

#### Step 2: 构建前端

```bash
cd ~/gitee-software/sw-projects/sw-dashboard/frontend
npm ci
npm run build
cd ..
```

#### Step 3: 创建 systemd 服务

```bash
sudo tee /etc/systemd/system/sw-dashboard.service > /dev/null <<'EOF'
[Unit]
Description=sw-dashboard — 翠花集群管理面板
After=network.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/home/ubuntu/gitee-software/sw-projects/sw-dashboard/backend
ExecStart=/home/ubuntu/gitee-software/sw-projects/sw-dashboard/venv/bin/uvicorn main:app --host 0.0.0.0 --port 8900 --workers 1
Restart=on-failure
RestartSec=5
StartLimitIntervalSec=60
StartLimitBurst=3

Environment=HERMES_DASHBOARD_TOKEN=your-strong-token-here

StandardOutput=journal
StandardError=journal
SyslogIdentifier=sw-dashboard

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
```

#### Step 4: 启动服务

```bash
sudo systemctl enable sw-dashboard
sudo systemctl restart sw-dashboard
sudo systemctl status sw-dashboard --no-pager
```

#### Step 5: 验证部署

```bash
# 健康检查
curl http://localhost:8900/api/health

# 访问前端页面
# 打开浏览器访问: http://<服务器IP>:8900
```

## 3. 部署方式说明

### 3.1 架构概览

```
┌─────────────────────────────────────────────────┐
│                    Tailscale 内网                  │
│                                                     │
│    ┌──────────────┐      ┌──────────────────────┐  │
│    │   浏览器     │ ───→ │   sw-dashboard:8900   │  │
│    │  (管理员)    │      │                       │  │
│    └──────────────┘      │  ┌─────────────────┐  │  │
│                          │  │   Uvicorn        │  │  │
│                          │  │   (FastAPI)      │  │  │
│                          │  │                  │  │  │
│                          │  │  ┌─ API 路由     │  │  │
│                          │  │  └─ 静态文件挂载  │  │  │
│                          │  └─────────────────┘  │  │
│                          └──────────────────────┘  │
└─────────────────────────────────────────────────┘
```

### 3.2 为什么选择 systemd 直接部署？

- **内存占用低**：Uvicorn 单 worker 约 50-80MB，而 Docker 需额外 50-100MB 开销
- **启动快**：无需容器化流程，秒级启动
- **管理简便**：与系统服务管理一体化，journald 统一日志
- **资源适配**：512MB 旧云服务器的最佳选择

### 3.3 前端部署说明

前端采用 Vue 3 + Vite 构建，产物在 `frontend/dist/` 目录。

后端 `main.py` 通过 FastAPI 的 `StaticFiles` 将 `frontend/dist/` 挂载到 `/` 路径：

```python
frontend_dist = backend_dir.parent / "frontend" / "dist"
if frontend_dist.exists():
    app.mount("/", StaticFiles(directory=str(frontend_dist), html=True), name="frontend")
```

> **注意**：前端静态文件首次部署后不需要重复构建，除非修改了前端代码。

## 4. 环境变量说明

### 4.1 必填变量

| 变量名 | 说明 | 默认值 | 是否必填 |
|--------|------|--------|----------|
| `HERMES_DASHBOARD_TOKEN` | API 认证 Token | `dev-token-123456` | **是**（生产环境必须修改） |

> **⚠ 安全提醒**：生产环境务必设置强 Token，长度不少于 32 位，避免使用默认值。

### 4.2 可选变量

| 变量名 | 说明 | 默认值 |
|--------|------|--------|
| `AGENTS_WORKSPACE_PATH` | Agent 工作空间路径 | `~/gitee-software/sw-agents-workspace` |
| `SKILLS_LIBRARY_PATH` | 技能库路径 | `~/gitee-software/sw-skills-library` |
| `PROJECTS_PATH` | 项目路径 | `~/gitee-software/sw-projects` |
| `HERMES_HOME` | Hermes 配置文件目录 | `/home/ubuntu/.hermes/profiles/software-dev` |
| `LOG_PATH` | 日志路径 | `~/.hermes/hermes-agent/venv/var/log` |
| `SKILLS_PATH` | 技能数据路径 | `~/.hermes/skills` |

### 4.3 设置环境变量

**方式一：export（临时）**

```bash
export HERMES_DASHBOARD_TOKEN="your-strong-token"
```

**方式二：写入 systemd 服务文件（推荐）**

```bash
# 在 [Service] 段添加
Environment=HERMES_DASHBOARD_TOKEN=your-strong-token
```

**方式三：写入 .env 文件**

```bash
echo 'HERMES_DASHBOARD_TOKEN=your-strong-token' >> ~/.hermes/.env
```

## 5. systemd 服务管理

### 5.1 基本操作

```bash
# 启动
sudo systemctl start sw-dashboard

# 停止
sudo systemctl stop sw-dashboard

# 重启
sudo systemctl restart sw-dashboard

# 查看状态
sudo systemctl status sw-dashboard

# 开机自启
sudo systemctl enable sw-dashboard

# 关闭自启
sudo systemctl disable sw-dashboard
```

### 5.2 查看日志

```bash
# 实时日志
sudo journalctl -u sw-dashboard -f

# 最近 100 行
sudo journalctl -u sw-dashboard -n 100 --no-pager

# 指定时间范围
sudo journalctl -u sw-dashboard --since "5 min ago"
sudo journalctl -u sw-dashboard --since today

# 按日志级别过滤
sudo journalctl -u sw-dashboard -p err
```

### 5.3 服务配置文件位置

```
/etc/systemd/system/sw-dashboard.service
```

修改后执行 `sudo systemctl daemon-reload` 使其生效。

## 6. 日志管理

### 6.1 日志位置

| 日志类型 | 路径 |
|----------|------|
| 标准输出 | journald（`journalctl -u sw-dashboard`） |
| 应用日志 | `~/.hermes/hermes-agent/venv/var/log/` |

### 6.2 日志轮转

journald 默认按大小轮转，可以通过以下配置限制日志体积：

```bash
# 查看当前 journald 用量
journalctl --disk-usage

# 限制 journal 日志大小（可选）
sudo journalctl --vacuum-size=200M
```

## 7. 常见问题

### 7.1 服务启动失败

```bash
# 查看详细日志
sudo journalctl -u sw-dashboard -n 50 --no-pager

# 常见原因：
# 1. 端口 8900 被占用 → 检查: sudo lsof -i :8900
# 2. Python 依赖缺失 → 重新执行: source venv/bin/activate && pip install -r backend/requirements.txt
# 3. 前端文件缺失 → 重新构建: cd frontend && npm ci && npm run build
```

### 7.2 端口冲突

```bash
# 检查端口占用
sudo lsof -i :8900

# 如需更改端口，修改 systemd 服务中的 --port 参数
# 然后重启
sudo systemctl daemon-reload
sudo systemctl restart sw-dashboard
```

### 7.3 前端页面空白

```bash
# 确认前端 dist 目录存在
ls -la frontend/dist/

# 如果没有，重新构建
cd frontend && npm ci && npm run build && cd ..
```

### 7.4 认证失败

```bash
# 确认环境变量已正确设置
echo $HERMES_DASHBOARD_TOKEN

# 在 systemd 服务中检查 Environment 行
sudo grep Environment /etc/systemd/system/sw-dashboard.service

# Token 应由 Header 传递: Authorization: Bearer <token>
```

## 8. Docker 部署（备选）

> 如服务器内存充足（≥1GB），或需要容器化隔离，可使用 Docker 部署。

### 8.1 构建镜像

```bash
cd ~/gitee-software/sw-projects/sw-dashboard
docker build -t sw-dashboard:latest -f deploy/docker/Dockerfile .
```

### 8.2 启动容器

```bash
docker run -d \
  --name sw-dashboard \
  --restart unless-stopped \
  -p 8900:8900 \
  -e HERMES_DASHBOARD_TOKEN="your-strong-token" \
  -v sw-dashboard-data:/data \
  sw-dashboard:latest
```

### 8.3 使用 docker-compose

```bash
cd ~/gitee-software/sw-projects/sw-dashboard
export HERMES_DASHBOARD_TOKEN="your-strong-token"
docker compose -f deploy/docker/docker-compose.yml up -d
```
