## 1. 环境要求

### 1.1 软件要求

| 组件 | 最低版本 | 推荐版本 |
|:-----|:---------|:---------|
| Docker | 24.0+ | 27.0+ |
| Docker Compose | V2（`docker compose`） | V2.27+ |
| curl | 7.0+ | 8.0+ |

### 1.2 验证安装

```bash
# 检查 Docker
docker --version
# 预期输出示例：Docker version 27.0.0, build abc123

# 检查 Docker Compose
docker compose version
# 预期输出示例：Docker Compose version v2.27.0

# 检查 curl
curl --version
```

### 1.3 资源要求

| 资源 | 最低 | 建议 |
|:-----|:-----|:-----|
| CPU | 2 核 | 4 核 |
| 内存 | 4 GB | 8 GB |
| 磁盘 | 10 GB 可用 | 20 GB 可用 |

### 1.4 端口占用

调试环境启动后会占用以下默认端口：

| 端口 | 服务 | 说明 |
|:-----|:-----|:------|
| 8080 | 前端 Web | Nginx 静态代理 |
| 8081 | 后端 API | Go 应用（可调）|
| 5432 | PostgreSQL | 数据库（可调）|
| 2345 | Delve | 调试端口（可调）|

> 如果宿主机端口冲突，可通过 `.env` 文件修改 `API_PORT`、`WEB_PORT`、`DB_PORT`。

## 2. 快速启动

### 2.1 一键启动

```bash
# 在项目根目录执行
./start-dev.sh
```

脚本会自动完成以下步骤：

1. ✅ Docker / Docker Compose 环境检查
2. ✅ `.env` 文件创建（从 `.env.example` 复制）
3. ✅ 前端构建检查（`frontend/dist` 是否就绪）
4. ✅ Docker Compose 构建并启动（后端 + 数据库 + 前端）
5. ✅ 健康检查（等待后端 `/health` 就绪）

### 2.2 启动成功标志

看到以下输出表示启动成功：

```
╔════════════════════════════════════════════╗
║  ✅ 调试环境就绪！                        ║
╠════════════════════════════════════════════╣
║  后端 API:  http://localhost:8081          ║
║  前端 Web:  http://localhost:8080          ║
║  数据库:    localhost:5432                 ║
║  调试端口:  localhost:2345                 ║
╚════════════════════════════════════════════╝
```

### 2.3 访问测试

| 入口 | URL | 预期结果 |
|:-----|:----|:---------|
| 健康检查 | `http://localhost:8081/health` | `{"status":"ok","ts":...}` |
| API 文档 | `http://localhost:8081/api/v1/auth/login` | POST 返回 JSON |
| 前端页面 | `http://localhost:8080` | 智学助手登录页 |
| 数据库 | `psql -h localhost -p 5432 -U smart_learning -d smart_learning` | 连接成功 |

### 2.4 停止环境

```bash
# 停止并保留数据
docker compose -f deploy/docker/docker-compose.yml down

# 停止并删除数据卷（⚠️ 会清空数据库数据）
docker compose -f deploy/docker/docker-compose.yml down -v
```

## 3. 环境变量说明

### 3.1 完整变量清单

| 变量名 | 默认值 | 说明 |
|:-------|:-------|:------|
| `API_PORT` | `8081` | 后端 API 映射到宿主机的端口 |
| `WEB_PORT` | `8080` | 前端 Web 映射到宿主机的端口 |
| `DB_PORT` | `5432` | 数据库映射到宿主机的端口 |
| `DEBUG_PORT` | `2345` | Delve 调试端口 |
| `DB_USER` | `smart_learning` | 数据库用户 |
| `DB_PASSWORD` | `smart_learning` | 数据库密码 |
| `DB_NAME` | `smart_learning` | 数据库名称 |
| `JWT_SECRET` | `dev-secret-...` | JWT 签名密钥 |
| `JWT_ACCESS_TTL` | `2h` | Access Token 有效期 |
| `JWT_REFRESH_TTL` | `168h` | Refresh Token 有效期 |
| `LOG_LEVEL` | `debug` | 日志级别 |
| `SERVER_MODE` | `debug` | Gin 运行模式 |
| `APP_ENV` | `dev` | 应用环境 |
| `CORS_ALLOW_ORIGINS` | `http://localhost:8080,http://localhost:5173` | CORS 白名单 |

### 3.2 配置优先级

```
环境变量 > .env 文件 > Docker Compose 默认值 > Go 代码默认值
```

### 3.3 修改配置

```bash
# 方式一：直接修改 deploy/config/development/.env
vim deploy/config/development/.env

# 方式二：通过 export 临时覆盖
export API_PORT=9090
export DB_PASSWORD=my_strong_password
./start-dev.sh
```

### 3.4 ⚠️ 密码安全提醒

调试环境的默认密码为 `smart_learning`，**仅适用于本地调试**。如果环境暴露在网络中：

1. **必须修改 `DB_PASSWORD`** 为强密码
2. **必须修改 `JWT_SECRET`** 为 32 位以上随机字符串
3. 使用以下命令生成随机密钥：

```bash
# 生成 32 位随机 JWT_SECRET
openssl rand -hex 16

# 生成 32 位随机 DB_PASSWORD
openssl rand -base64 24
```

## 4. 服务访问

### 4.1 后端 API

后端运行在容器 `backend:8080`，宿主机映射端口 `API_PORT`（默认 8081）。

```bash
# 健康检查
curl http://localhost:8081/health

# 用户注册
curl -X POST http://localhost:8081/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{"phone":"13800138000","password":"Test1234","nickname":"测试用户"}'

# 用户登录
curl -X POST http://localhost:8081/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"phone":"13800138000","password":"Test1234"}'
```

### 4.2 前端 Web

前端运行在容器 `frontend:80`，宿主机映射端口 `WEB_PORT`（默认 8080）。

浏览器打开 `http://localhost:8080` 即可访问智学助手 Web 界面。

> 前端通过 Nginx 代理 `/api/` 路径到后端，无需额外配置跨域。

### 4.3 数据库

数据库运行在容器 `db:5432`，宿主机映射端口 `DB_PORT`（默认 5432）。

```bash
# 通过宿主机连接
psql -h localhost -p 5432 -U smart_learning -d smart_learning

# 进入容器连接
docker exec -it smart-learning-db psql -U smart_learning -d smart_learning
```

### 4.4 服务间通信

| 源 | 目标 | 地址 |
|:---|:-----|:------|
| 前端 Nginx | 后端 API | `http://backend:8080` |
| 后端 Go | 数据库 | `db:5432` |
| 宿主机 | 后端 API | `localhost:${API_PORT}` |
| 宿主机 | 前端 Web | `localhost:${WEB_PORT}` |
| 宿主机 | 数据库 | `localhost:${DB_PORT}` |

## 5. 常用调试命令

### 5.1 日志查看

```bash
# 查看所有服务的日志（实时）
docker compose -f deploy/docker/docker-compose.yml logs -f

# 查看后端日志
docker compose -f deploy/docker/docker-compose.yml logs -f backend

# 查看数据库日志
docker compose -f deploy/docker/docker-compose.yml logs -f db

# 查看前端日志
docker compose -f deploy/docker/docker-compose.yml logs -f frontend

# 查看最近 100 行日志
docker compose -f deploy/docker/docker-compose.yml logs --tail=100 backend
```

### 5.2 服务管理

```bash
# 重启单个服务
docker compose -f deploy/docker/docker-compose.yml restart backend

# 重新构建并启动
docker compose -f deploy/docker/docker-compose.yml up -d --build backend

# 停止所有服务
docker compose -f deploy/docker/docker-compose.yml stop

# 启动所有服务
docker compose -f deploy/docker/docker-compose.yml start

# 完全停止并清理
docker compose -f deploy/docker/docker-compose.yml down
```

### 5.3 进入容器

```bash
# 进入后端容器
docker exec -it smart-learning-backend sh

# 进入数据库容器
docker exec -it smart-learning-db sh

# 进入前端容器
docker exec -it smart-learning-frontend sh
```

### 5.4 调试后端（Delve）

调试版 Dockerfile 暴露了端口 2345，支持 Delve 远程调试：

```bash
# 宿主机上连接 Delve
dlv connect localhost:2345
```

> 注意：当前调试版 Dockerfile 未内置 delve 二进制。如需使用，请在 Dockerfile 的 builder stage 中添加 Delve 安装步骤：
>
> ```dockerfile
> RUN go install github.com/go-delve/delve/cmd/dlv@latest
> ```
>
> 并将 ENTRYPOINT 改为：
>
> ```dockerfile
> ENTRYPOINT ["dlv", "--listen=:2345", "--headless=true", "--api-version=2", "--accept-multiclient", "exec", "/server"]
> ```

### 5.5 数据导出

```bash
# 导出数据库备份
docker exec -t smart-learning-db pg_dump -U smart_learning smart_learning > backup_$(date +%Y%m%d_%H%M%S).sql

# 从备份恢复
cat backup.sql | docker exec -i smart-learning-db psql -U smart_learning -d smart_learning
```

### 5.6 资源监控

```bash
# 查看容器资源使用
docker stats smart-learning-backend smart-learning-db smart-learning-frontend

# 查看所有容器状态
docker compose -f deploy/docker/docker-compose.yml ps
```

## 6. 数据库管理

### 6.1 连接方式

```bash
# 方式一：宿主机连接（需要本地安装 psql）
psql -h localhost -p 5432 -U smart_learning -d smart_learning

# 方式二：容器内连接
docker exec -it smart-learning-db psql -U smart_learning -d smart_learning

# 方式三：一行执行 SQL
docker exec -it smart-learning-db psql -U smart_learning -d smart_learning -c "SELECT count(*) FROM users;"
```

### 6.2 常用 SQL

```sql
-- 查看所有表
\dt

-- 查看表结构
\d+ users

-- 查看用户数
SELECT count(*) FROM users;

-- 查看最近注册的用户
SELECT id, phone, nickname, created_at FROM users ORDER BY created_at DESC LIMIT 10;

-- 查看最近练习记录
SELECT id, user_id, score, created_at FROM exercise_records ORDER BY created_at DESC LIMIT 10;
```

### 6.3 数据库迁移

调试环境下，GORM `AutoMigrate` 会在后端启动时自动创建/更新表结构。

```go
// 对应 main.go 中的 AutoMigrate 调用
db.AutoMigrate(
    &model.User{},
    &model.Subject{},
    &model.KnowledgePoint{},
    &model.Question{},
    &model.StudyPlan{},
    &model.StudyRecord{},
    &model.ExerciseRecord{},
    &model.MistakeBook{},
    &model.StudyReport{},
    &model.ModelSetting{},
)
```

> **注意**：AutoMigrate 只会新增列/表，不会删除已有列。
> 生产环境建议使用 [golang-migrate](https://github.com/golang-migrate/migrate) 版本化迁移。

### 6.4 初始化脚本

容器启动时会自动执行 `deploy/docker/init-scripts/` 目录下的 `.sql` 文件。
如需种子数据，请在 `00-init.sql` 中添加 INSERT 语句。

### 6.5 重置数据库

```bash
# 方式一：删除数据卷（会清空所有数据）
docker compose -f deploy/docker/docker-compose.yml down -v
docker compose -f deploy/docker/docker-compose.yml up -d

# 方式二：保留 Volume 但清空表（在 psql 中执行）
TRUNCATE TABLE users CASCADE;
-- 或删除所有数据
DROP SCHEMA public CASCADE;
CREATE SCHEMA public;
```

## 7. 常见问题排查

### Q1：端口被占用

**现象**：启动时提示 `port is already allocated` 或类似错误。

**解决方案**：

```bash
# 1. 查看端口占用
lsof -i :8081

# 2. 修改 .env 中的端口
echo "API_PORT=9090" >> deploy/config/development/.env
echo "WEB_PORT=9091" >> deploy/config/development/.env

# 3. 重新启动
./start-dev.sh
```

### Q2：数据库连接失败

**现象**：后端日志出现 `连接 PostgreSQL 失败` 或 `dial tcp: lookup db` 错误。

**解决方案**：

```bash
# 1. 检查数据库容器是否启动
docker ps | grep smart-learning-db

# 2. 查看数据库日志
docker compose -f deploy/docker/docker-compose.yml logs db

# 3. 检查数据库健康状态
docker inspect smart-learning-db --format='{{.State.Health.Status}}'

# 4. 等待数据库就绪后重启后端
docker compose -f deploy/docker/docker-compose.yml restart backend
```

### Q3：前端页面白屏或 404

**现象**：浏览器访问 `http://localhost:8080` 显示空白页或 404。

**解决方案**：

```bash
# 1. 检查前端构建产物是否存在
ls -la frontend/dist/index.html

# 2. 如果不存在，重新构建前端
cd frontend
npm install
npm run build
cd ..

# 3. 重启前端容器
docker compose -f deploy/docker/docker-compose.yml restart frontend

# 4. 查看 Nginx 日志
docker compose -f deploy/docker/docker-compose.yml logs frontend
```

### Q4：API 请求返回 502 Bad Gateway

**现象**：前端请求 API 时返回 502 错误。

**解决方案**：

```bash
# 1. 检查后端容器是否正常运行
docker ps | grep smart-learning-backend

# 2. 查看后端日志
docker compose -f deploy/docker/docker-compose.yml logs backend

# 3. 检查 Nginx 配置是否正确
docker exec smart-learning-frontend nginx -t

# 4. 重启后端
docker compose -f deploy/docker/docker-compose.yml restart backend
```

### Q5：Docker 构建失败

**现象**：`docker compose up -d --build` 构建过程中报错。

**解决方案**：

```bash
# 1. 单独构建后端镜像，查看详细错误
docker build -f deploy/docker/Dockerfile -t smart-learning-backend:debug ../../backend

# 2. 检查 Go 模块依赖
cd backend
go mod tidy
go build ./cmd/server
cd ..

# 3. 清理 Docker 构建缓存
docker builder prune -f

# 4. 尝试拉取基础镜像
docker pull golang:1.25-alpine
docker pull alpine:3.21
docker pull postgres:16-alpine
docker pull nginx:1.27-alpine
```

### Q6：JWT_SECRET 警告

**现象**：启动时看到 `[WARN] JWT_SECRET 仍为占位密钥` 的警告。

**解决方案**：

```bash
# 生成随机 JWT_SECRET
NEW_SECRET=$(openssl rand -hex 16)
echo "JWT_SECRET=$NEW_SECRET" >> deploy/config/development/.env

# 重启后端容器
docker compose -f deploy/docker/docker-compose.yml restart backend
```

> 调试环境下这个警告不影响使用，但部署到生产环境前必须替换。

### Q7：AutoMigrate 报错

**现象**：后端日志出现 `automigrate failed` 或数据库迁移错误。

**解决方案**：

```bash
# 1. 检查数据库连接是否正常
docker exec -it smart-learning-db psql -U smart_learning -d smart_learning -c "SELECT 1"

# 2. 查看具体错误信息
docker compose -f deploy/docker/docker-compose.yml logs backend | grep -i "migrate\|error"

# 3. 如果表结构冲突，可以重置数据库后再试
docker compose -f deploy/docker/docker-compose.yml down -v
docker compose -f deploy/docker/docker-compose.yml up -d
```

### Q8：Docker Compose 命令不存在

**现象**：提示 `docker compose: command not found`。

**解决方案**：

```bash
# 1. 检查 Docker 版本（旧版使用 docker-compose）
docker --version

# 2. 如果使用旧版 Docker，使用 docker-compose 替代
docker-compose -f deploy/docker/docker-compose.yml up -d --build

# 3. 或者升级 Docker
# Ubuntu:
sudo apt-get update
sudo apt-get install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

### Q9：宿主机无法连接数据库

**现象**：`psql -h localhost -p 5432 -U smart_learning` 连接失败。

**解决方案**：

```bash
# 1. 确认端口映射是否正确
docker port smart-learning-db

# 2. 如果端口被占用，修改 DB_PORT
echo "DB_PORT=15432" >> deploy/config/development/.env
docker compose -f deploy/docker/docker-compose.yml down
docker compose -f deploy/docker/docker-compose.yml up -d

# 3. 使用新端口连接
psql -h localhost -p 15432 -U smart_learning -d smart_learning
```

### Q10：跨域请求失败

**现象**：前端访问 API 时浏览器控制台出现 CORS 错误。

**解决方案**：

```bash
# 1. 检查 CORS_ALLOW_ORIGINS 配置
echo $CORS_ALLOW_ORIGINS

# 2. 如果通过不同端口访问前端，添加对应来源
echo "CORS_ALLOW_ORIGINS=http://localhost:8080,http://localhost:5173,http://192.168.1.100:8080" >> deploy/config/development/.env

# 3. 重启后端使配置生效
docker compose -f deploy/docker/docker-compose.yml restart backend
```
