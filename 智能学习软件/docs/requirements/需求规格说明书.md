> 版本：v0.1.0（草案）
> 项目类型：fullstack
> 最后更新：2026-06-29
> 优先级标注：P0（MVP必需）/ P1（重要·可分期）/ P2（锦上添花）/ P3（未来规划）

## 1. 项目概述

### 1.1 业务背景

当前中小学生面临**题海战术**的困境——每日数百题的刷题量，老师通过小程序或练习册线下布置。尽管市面上已有作业帮、小猿搜题等拍照识别类 APP 解决了"记录错题"的问题，但在**错题后的精准练习、举一反三、知识图谱可视化、知识点推演与检测**等方向尚无成熟方案。

本产品旨在通过 AI 引擎 + 知识图谱技术，构建从"记录错题"到"学会为止"的完整学习闭环。

### 1.2 业务目标

| 目标 | 描述 |
|:----|:------|
| G1 | 自动捕获学生各周期错题，打上周期标签，形成结构化错题本 |
| G2 | 基于错题 AI 自动生成变式题，实现举一反三的精准练习 |
| G3 | 以知识图谱方式展示题目与知识点的关联，指引最优学习路径 |
| G4 | 以可视化图表呈现知识点掌握度、进步情况、薄弱点分析 |

### 1.3 核心名词解释

| 术语 | 说明 |
|:----|:------|
| 三周期 | 每日错题 / 每周错题 / 单元（考试）周期错题 |
| 变式题 | 与错题考察同一知识点，但改变数字/问法/情境的同类型题目 |
| 熔断机制 | 同一知识点做错后，自动触发变式题练习，直到做对为止（最多 3 次） |
| 知识图谱 | 以图结构组织的知识点网络，各知识点之间存在前置/后继/关联关系 |
| 知识点掌握度 | 基于正确率、练习次数、题目难度等综合计算的知识精通程度 |

## 3. 功能需求

### 3.1 P0 — MVP 必需功能（不做不能上线）

#### F1 错题捕获与三周期标记

| 属性 | 内容 |
|:----|:------|
| **用户故事** | 作为一名学生，我希望能通过拍照快速录入错题，并让系统自动打上「每日/每周/单元」周期标签，以便我按周期维度复习错题。 |
| **描述** | 学生拍照上传错题 → OCR 识别题目文字 → 系统自动将错题归入对应的周期分类（每日/每周/单元）。三周期基于时间自动熔断：当日的归每日、本周的归每周、最近一次考试的归单元。 |
| **归属** | iOS 客户端 + 后端 |
| **验收条件（DoD）** | ① 拍照后 5s 内完成 OCR 识别题面；② 支持批量和单题拍照；③ 系统自动按日期/考试事件分配周期标签；④ 学生可在错题列表中按周期筛选查看 |
| **优先级** | P0 |

#### F2 举一反三变式题推荐

| 属性 | 内容 |
|:----|:------|
| **用户故事** | 作为一名学生，我希望能针对做错的题目，得到 AI 自动生成的同类变式题（换数字/换问法），连续做对为止（最多 3 次），以实现举一反三。 |
| **描述** | 学生对某道错题查看解析后 → 点击"举一反三" → 系统调用 AI 引擎基于原题的知识点和题型生成变式题 → 学生作答 → 如果正确则通过，错误则再生成下一道变式（最多 3 轮）。3 轮全错则标记为"需人工辅导"。 |
| **归属** | iOS 客户端 + AI 引擎 + 后端 |
| **验收条件（DoD）** | ① 每道错题支持一键触发变式题；② AI 生成的变式题与原题考察同一知识点；③ 每道变式题包含题目、选项/填空、答案和解析；④ 正确→标记通过；错误→再生成（最多 3 次）；⑤ 3 次全错→标记"需人工辅导" |
| **优先级** | P0 |

#### F3 知识图谱可视化

| 属性 | 内容 |
|:----|:------|
| **用户故事** | 作为一名学生，我希望能以图的方式看到题目和知识点的关联关系，以及系统推荐的下一步学习路径，以便我知道该重点学什么。 |
| **描述** | 系统以力导向图/树状图展示知识点网络 → 每个知识点节点关联该知识点的错题数量、掌握度 → 用颜色/大小区分掌握程度 → 算法推荐从薄弱知识点开始的"最优学习路径"。 |
| **归属** | iOS 客户端（图表渲染） + 后端（图谱数据） + AI 引擎（路径推荐） |
| **验收条件（DoD）** | ① 知识点以节点+连线的图结构展示；② 节点颜色反映掌握度（红/黄/绿）；③ 点击节点可查看对应错题列表；④ 系统推荐一条"从薄弱点到基础点"的学习路径；⑤ 支持缩放和拖动 |
| **优先级** | P0 |

#### F4 学习结果可视化

| 属性 | 内容 |
|:----|:------|
| **用户故事** | 作为一名学生/家长，我希望能通过图表直观了解知识点掌握度、进步趋势和薄弱点分布，以便调整学习重点。 |
| **描述** | 仪表盘页面展示：① 知识点掌握度雷达图（多学科/多维度）；② 近期进步曲线（时间 vs 正确率）；③ 薄弱知识点排行榜（按错误次数降序）；④ 整体学习进度（已完成知识点/总知识点）。家长可查看孩子的汇总数据。 |
| **归属** | iOS 客户端（ECharts/Charts） + 后端（统计聚合） |
| **验收条件（DoD）** | ① 雷达图展示至少 6 个维度的知识模块掌握度；② 进步曲线支持 7 天/30 天/学期时间切换；③ 薄弱点排行可点击跳转至对应错题；④ 学生和家长端数据实时一致 |
| **优先级** | P0 |

### 3.2 P1 — 重要功能（可分期交付）

#### F5 手动错题录入

| 属性 | 内容 |
|:----|:------|
| **用户故事** | 作为一名学生，除了拍照外，我还希望能手动录入错题（文字或图片选择），方便处理不便拍摄的场景。 |
| **描述** | 支持从相册选图、文本粘贴、手写输入等方式录入错题。 |
| **优先级** | P1 |

#### F6 知识点推演与路径推荐

| 属性 | 内容 |
|:----|:------|
| **用户故事** | 作为一名学生，我希望系统能告诉我这个知识点前置需要掌握哪些基础，以及下一步该学什么。 |
| **描述** | 基于知识图谱的拓扑结构，对一个未掌握的知识点向前溯源（前置知识点）、向后推荐（后继知识点），形成个性化学习路径。 |
| **优先级** | P1 |

#### F7 错题批量操作与管理

| 属性 | 内容 |
|:----|:------|
| **用户故事** | 作为一名学生，我希望能够批量导出、删除、标记"已掌握"错题，以保持错题本的整洁。 |
| **描述** | 支持批量选择错题进行：标记已掌握 / 删除 / 导出 PDF / 加入练习计划。 |
| **优先级** | P1 |

## 4. MVP 范围定义

### 4.1 第一期（MVP）范围 — 做什么

| 维度 | 内容 |
|:-----|:------|
| **用户** | 学生 + 家长 |
| **核心功能** | F1 错题捕获与三周期标记（P0）、F2 举一反三变式题推荐（P0）、F3 知识图谱可视化（P0）、F4 学习结果可视化（P0） |
| **客户端** | iPad 优先，兼容 iPhone 竖屏 |
| **后端** | Go + PostgreSQL + AI 引擎（接入大模型 API） |
| **认证** | 手机号+验证码登录 / 微信快捷登录 |

### 4.2 第一期（MVP）范围 — 不做

| 维度 | 说明 |
|:-----|:------|
| ❌ 老师端 | 暂不支持老师角色，无班级管理、作业布置功能 |
| ❌ 智能学习计划 | F11 延至 P3 |
| ❌ 班级学情对比 | F12 延至 P3 |
| ❌ 错题打印 | F13 延至 P3 |
| ❌ 多学科 | MVP 先聚焦一个学科（数学），后续扩展到更多学科 |

### 4.3 分期规划

| 版本 | 周期 | 包含功能 | 说明 |
|:-----|:-----|:---------|:------|
| v1.0（MVP） | T0 | F1+F2+F3+F4 | 核心学习闭环：错题录入→变式练习→知识图谱→结果可视化 |
| v1.1 | T0+2w | F5+F6+F7 | 手动录入、知识点推演、批量管理 |
| v1.2 | T0+4w | F8+F9+F10 | 分享、成就、深色模式 |
| v2.0 | 下一学期 | F11+F12+F13 | 智能学习计划、班级对比、打印功能 |

## 5. 非功能需求

| 类别 | 需求 | 说明 |
|:-----|:------|:------|
| **性能** | OCR 识别 ≤5s | 拍照上传到题面识别完成，用户等待时间 ≤5 秒 |
| **性能** | 变式题生成 ≤8s | AI 引擎调用大模型生成变式题，响应时间 ≤8 秒 |
| **性能** | 页面加载 ≤2s | 核心页面（错题列表、知识图谱、仪表盘）首屏加载 ≤2 秒 |
| **可用性** | 平板优先适配 | iPad 布局为设计基准，同时兼容 iPhone 竖屏 |
| **可靠性** | 数据持久化 | 错题数据、学习记录永久保存，支持多设备备份 |
| **安全** | 数据隐私 | 学生数据不共享、不对外暴露，符合未成年人数据保护要求 |
| **扩展性** | 多学科支持 | 架构支持后续扩展到数学、英语、物理等多学科知识图谱 |
| **易用性** | 零学习成本 | 学生打开即用，无需教程，拍照→练习→看报告三步走 |

## 6. 技术约束

| 约束 | 说明 |
|:-----|:------|
| 后端语言 | Go |
| 数据库 | PostgreSQL |
| AI 引擎 | 调用大模型 API（如 GPT / 文心一言 / 通义千问），用于 OCR + 变式题生成 + 知识图谱推理 |
| 前端框架 | iOS 原生（Swift/SwiftUI）+ 图表库（如 Charts / SpriteKit for 图谱） |
| 部署方式 | Docker 容器化 |
| 代码管理 | Gitee |
| 第三方依赖 | OCR 服务（可自建或调用云服务）、大模型 API、云存储（OSS/COS） |
