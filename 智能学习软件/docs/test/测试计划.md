## 5. 测试类型与用例设计

### 5.1 单元测试（已通过）

**目标**：函数级逻辑正确性

**覆盖**：
- ✅ Auth：注册/登录/刷新/Mask
- ✅ User：获取/更新/改密/头像
- ✅ Plan：创建/查询/更新/删除/AI 生成/打卡
- ✅ Exercise：批改/随机/推荐/列表
- ✅ Mistake：收录/标记掌握/重练/分组
- ✅ Report：概览/详情/掌握度/趋势

**用例设计原则**：
- 正常路径（Happy Path）
- 边界值（空字符串、超大值）
- 异常路径（Not Found / Forbidden / Conflict）
- 幂等性（重复错题收录）

### 5.2 集成测试（待补充）

**目标**：Service × Repository 协作

**应覆盖场景**：
1. JWT 中间件拦截 401 → handler 异常
2. Repository 查询 → Service 计算 → Handler 响应完整链路
3. 跨表事务（练习记录 + 错题收录）
4. 用户隔离（A 用户不可操作 B 用户数据）

### 5.3 E2E HTTP 测试（待补充）

**目标**：完整 HTTP 链路

**应覆盖场景**：
- 注册 → 登录 → 访问 /users/me
- 创建计划 → AI 生成 → 打卡
- 提交练习（答对 + 答错）→ 错题收录 → 重练
- 学习报告 Summary/Detail/Mastery/Trend
- Token 过期 → 刷新 → 重试

### 5.4 性能测试（NFR 验证）

| NFR | 目标 | 验证方法 |
|:-----|:-----|:---------|
| NF-01 首屏 ≤ 2s | HTTP API P95 | `go test -bench` + `vegeta` |
| NF-02 批改 ≤ 1s | `/exercises/submit` P95 | E2E 计时 |
| NF-03 报告 ≤ 3s | `/reports/detail` P95 | E2E 计时 |
| NF-04 1000 并发 | API QPS | `wrk` 压测 |
| NF-05 AI ≤ 3s | MVP 走降级 | 跳过（不适用）|

### 5.5 安全测试

| 测试项 | 验证方法 |
|:-------|:---------|
| SQL 注入 | 尝试 `' OR 1=1 --` 等 payload |
| XSS | 提交 `<script>alert(1)</script>` |
| CSRF | Bearer Token 不依赖 Cookie，跳过 |
| JWT 伪造 | 篡改 alg=none、过期 token |
| 暴力破解 | 错误密码 N 次无锁定（MVP 妥协）|
| 越权访问 | A 用户访问 B 用户计划 |
| 信息泄露 | 错误信息含敏感字段 |
| 敏感字段脱敏 | 手机号/邮箱在 API 响应中已脱敏 |
