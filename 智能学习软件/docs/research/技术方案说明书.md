### 1.2 前后端分离方案

| 维度 | 方案 |
|:-----|:------|
| 架构模式 | 前后端完全分离，RESTful API 通信 |
| 前端 | Vue 3 SPA，部署在 Nginx 静态目录 |
| 后端 | Go 单体应用（MVP 阶段），后期可拆微服务 |
| 数据格式 | JSON over HTTP/HTTPS |
| 状态管理 | JWT Token（前端 localStorage），无状态后端 |
| 跨域处理 | Nginx 反向代理统一域名，避免跨域 |

## 2. 后端技术选型

### 2.1 Go Web 框架

| 框架 | 选择理由 | 版本 |
|:-----|:---------|:-----|
| **Gin** ✅ | 性能优异（基准测试领先），社区活跃，中间件生态丰富，学习曲线平缓 | v1.10+ |

**备选：**
- **Echo** — 性能相近，特性类似，但 Gin 社区和生态更大
- **Fiber** — 类 Express 风格，API 更简洁，但 Go 版本要求 >=1.18，且社区相对较小

**选型理由总结**：
| 维度 | Gin | Echo | Fiber |
|:-----|:----|:-----|:------|
| 性能 | ★★★★★ | ★★★★★ | ★★★★★ |
| 社区规模 | ★★★★★ | ★★★★ | ★★★ |
| 第三方中间件 | ★★★★★ | ★★★★ | ★★★ |
| 文档质量 | ★★★★ | ★★★★★ | ★★★★ |
| 团队熟悉度 | ★★★★ | ★★★ | ★★★ |

### 2.2 ORM 框架

| 框架 | 选择理由 |
|:-----|:---------|
| **GORM** ✅ | Go 最流行的 ORM（Star 35K+），功能全面（自动迁移、Hook、预加载、事务），与 Gin 生态契合度高 |

**备选：**
- **Ent** — Facebook 出品，类型安全，代码生成式 ORM，适合复杂数据模型，但学习曲线较陡
- **sqlx** — 轻量级 SQL 封装，无 ORM 能力，适合简单项目

**选型理由**：
| 维度 | GORM | Ent | sqlx |
|:-----|:-----|:----|:------|
| 易用性 | ★★★★★ | ★★★ | ★★★★ |
| 功能完整度 | ★★★★★ | ★★★★ | ★★ |
| 自动迁移 | ✅ | ✅ | ❌ |
| 学习成本 | 低 | 中高 | 低 |
| 类型安全 | 中等 | 强 | 弱 |
| 社区生态 | ★★★★★ | ★★★★ | ★★★ |

### 2.3 API 风格

| 维度 | 方案 |
|:-----|:------|
| 风格 | **RESTful**（符合技术约束） |
| 版本控制 | URL 路径版本 `/api/v1/` |
| 响应格式 | `{"code": 0, "message": "success", "data": {...}}` |
| 分页规范 | `?page=1&page_size=20` → `{"total": N, "items": [...], "page": 1}` |
| 错误处理 | HTTP 状态码 + 业务错误码（4xx/5xx + 业务 code） |

## 3. 数据库设计

### 3.1 数据库选择

| 维度 | PostgreSQL 15 |
|:-----|:--------------|
| 关系型一致性 | ✅ 强 ACID 支持，适合学习记录、错题管理等强一致性场景 |
| JSON 支持 | ✅ JSONB 类型可存储学习计划的 items、学习报告的 stats |
| 全文检索 | ✅ 内置全文检索，后期可支持题目搜索 |
| 数组类型 | ✅ 支持 tags 等数组字段 |
| 扩展生态 | ✅ pgvector（支持向量检索，未来可做语义搜索）|

### 3.2 核心表结构建议

```
-- 用户表
users
├── id (UUID, PK)
├── name (VARCHAR)
├── phone (VARCHAR, UNIQUE)
├── email (VARCHAR, UNIQUE)
├── password_hash (VARCHAR)
├── role (ENUM: student/teacher/admin/parent)
├── avatar_url (VARCHAR)
├── parent_id (UUID, FK → users.id, nullable)  -- 家长绑定
├── created_at (TIMESTAMP)
└── updated_at (TIMESTAMP)

-- 科目表
subjects
├── id (BIGSERIAL, PK)
├── name (VARCHAR)
├── description (TEXT)
└── created_at (TIMESTAMP)

-- 知识点表（树形结构）
knowledge_points
├── id (BIGSERIAL, PK)
├── subject_id (BIGINT, FK → subjects.id)
├── parent_id (BIGINT, FK → knowledge_points.id, nullable)
├── name (VARCHAR)
├── level (INT)
├── path (LTREE / MATERIALIZED PATH)  -- 便于树形查询
└── created_at (TIMESTAMP)

-- 题目表
questions
├── id (BIGSERIAL, PK)
├── subject_id (BIGINT, FK → subjects.id)
├── knowledge_point_id (BIGINT, FK → knowledge_points.id)
├── type (ENUM: choice/fill/judge/subjective)
├── difficulty (INT, 1-5)
├── content (JSONB)           -- 结构化题目内容
├── options (JSONB, nullable) -- 选择题选项
├── answer (TEXT)
├── analysis (TEXT)           -- 题目解析
└── created_at (TIMESTAMP)

-- 学习计划表
study_plans
├── id (BIGSERIAL, PK)
├── user_id (UUID, FK → users.id)
├── goal (TEXT)               -- 学习目标描述
├── start_date (DATE)
├── end_date (DATE)
├── items (JSONB)             -- 每日计划项 [{date, kp_ids, duration}]
├── status (ENUM: active/completed/archived)
└── created_at (TIMESTAMP)

-- 学习记录表
study_records
├── id (BIGSERIAL, PK)
├── user_id (UUID, FK → users.id)
├── plan_id (BIGINT, FK → study_plans.id)
├── date (DATE)
├── duration_min (INT)
├── status (ENUM: done/skip/partial)
├── memo (TEXT, nullable)
└── created_at (TIMESTAMP)

-- 练习记录表
exercise_records
├── id (BIGSERIAL, PK)
├── user_id (UUID, FK → users.id)
├── question_id (BIGINT, FK → questions.id)
├── answer (TEXT)
├── is_correct (BOOLEAN)
├── score (INT, nullable)           -- 主观题分数
├── duration_sec (INT, nullable)    -- 答题耗时
└── created_at (TIMESTAMP)

-- 错题本表
mistake_books
├── id (BIGSERIAL, PK)
├── user_id (UUID, FK → users.id)
├── question_id (BIGINT, FK → questions.id)
├── knowledge_point_id (BIGINT, FK → knowledge_points.id)
├── wrong_answer (TEXT)
├── mistake_count (INT, DEFAULT 1)
├── mastered (BOOLEAN, DEFAULT false)
├── mastered_at (TIMESTAMP, nullable)
├── last_reviewed_at (TIMESTAMP)
└── created_at (TIMESTAMP)

-- 学习报告表
study_reports
├── id (BIGSERIAL, PK)
├── user_id (UUID, FK → users.id)
├── period_type (ENUM: daily/weekly/monthly)
├── period_start (DATE)
├── period_end (DATE)
├── stats (JSONB)
│   ├── total_duration_min
│   ├── total_exercises
│   ├── correct_rate
│   ├── mastery_by_kp: [{kp_id, name, rate}]
│   └── streak_days
└── created_at (TIMESTAMP)
```

### 3.3 索引策略

| 表 | 索引 | 理由 |
|:---|:-----|:------|

| knowledge_points | (subject_id, level), parent_id | 知识点树形查询 |

### 3.4 数据迁移方案

## 4. AI 推荐引擎

### 4.1 第三方 LLM API 接入方案

| 维度 | 推荐方案 |
|:-----|:---------|
| 主选 | **通义千问 (Qwen)** — 国内延迟最低，性价比高，中文理解能力强 |
| 备选 | **文心一言 (ERNIE)** — 百度生态，教育领域有一定深度 |
| 备选 | **DeepSeek** — 数学推理能力强，适合题目解析场景 |

**接入架构**：
```
应用服务 (Go) → LLM Service (Go) → HTTP Client → 第三方 LLM API
                              ↕
                    缓存层 (Redis, TTL=1h)
```

**调用策略**：
- 对推荐结果做**缓存**：同一学生的相同场景，1 小时内不重复调用
- 设置 **超时 + 熔断**：3s 超时，连续 3 次失败熔断 30s
- **降级方案**：LLM 不可用时，回退到基于规则的推荐（按错题知识点 + 随机）
- **请求限流**：每个用户每分钟最多 5 次 AI 调用

### 4.2 推荐算法逻辑

| 场景 | 算法 | 数据输入 | 输出 |
|:-----|:-----|:---------|:-----|
| 智能排课计划 | LLM Prompt + 基于掌握度排序 | 知识点掌握率、时间约束、学习目标 | 每日学习计划 |
| 薄弱点推荐 | 错题知识点统计 + LLM 补强推荐 | 错题列表、知识点掌握度 | 推荐题目列表 |
| 计划调整 | LLM + 进度偏差分析 | 已完成/未完成比例、正确率趋势 | 调整后的计划 |
| 实时答题反馈 | 规则引擎（匹配答案） | 题目答案、学生答案 | 正误判断 + 解析 |

**推荐引擎的规则降级方案**（LLM 不可用时）：
1. **错题重练**：按知识点聚合，取出错次数最多的前 N 道题
2. **知识点练习**：按掌握率从低到高排序推荐
3. **计划生成**：基于时间约束 + 知识点数量平均分配

### 7.4 Nginx 配置要点

```nginx
# 前端静态资源
server {
    listen 80;
    server_name learn.example.com;

    # HTTPS 重定向
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name learn.example.com;

    ssl_certificate /etc/nginx/ssl/cert.pem;
    ssl_certificate_key /etc/nginx/ssl/key.pem;

    # 前端 SPA
    location / {
        root /usr/share/nginx/html;
        try_files $uri $uri/ /index.html;
    }

    # API 代理
    location /api/ {
        proxy_pass http://backend:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 超时配置
        proxy_connect_timeout 10s;
        proxy_read_timeout 30s;
    }

    # 静态资源缓存
    location /assets/ {
        root /usr/share/nginx/html;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}
```

## 8. 关键技术风险与应对

| 编号 | 风险 | 级别 | 应对策略 |
|:-----|:-----|:-----|:---------|
| R-01 | LLM API 调用延迟或不可用 | ⚠️ 高 | 规则降级引擎 + Redis 缓存 + 熔断机制 |
| R-02 | 题库数据不足导致推荐效果差 | ⚠️ 中 | 支持公开题库导入 + 教师手工录入双通道 |
| R-03 | 高并发下的数据库压力（高峰期）| ⚠️ 中 | Redis 缓存热点数据 + 读写分离（后期）|
| R-04 | 学生数据隐私合规风险 | ⚠️ 高 | 全量 HTTPS + 数据脱敏 + 最小权限原则 |
| R-05 | 前端移动端适配体验不一致 | ⚠️ 低 | 多设备测试 + 响应式断点方案 |
| R-06 | 知识图谱数据结构复杂 | ⚠️ 中 | 使用 adjacency list + materialized path 混合模型 |
| R-07 | JWT Token 安全风险 | ⚠️ 中 | 短时效 access_token + refresh_token + 黑名单机制 |
