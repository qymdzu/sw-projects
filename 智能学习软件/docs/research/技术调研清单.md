## 1. Go Web 框架对比

| 维度 | Gin | Echo | Fiber |
|:-----|:----|:-----|:------|
| **版本** | v1.10+ | v4.12+ | v2.52+ |
| **Star** | 78K+ | 30K+ | 34K+ |
| **性能 (req/s)** | ~55K | ~50K | ~59K (最高) |
| **路由** | 基于 httprouter，性能优异 | 基于 radix tree，支持参数路由 | 类 Express 风格，支持泛型 |
| **中间件生态** | 非常丰富（官方 + 社区 100+） | 丰富（50+） | 中等（30+） |
| **内置绑定/校验** | ShouldBind + validator v10 | Bind + validate | 自定义绑定 |
| **文档** | 详细，中文资料最多 | 良好，文档清晰 | 良好，但中文资料较少 |
| **学习曲线** | 低 | 低 | 低 |
| **社区活跃度** | ★★★★★ | ★★★★ | ★★★★ |
| **生产案例** | 大量（七牛、B站等国内企业） | 较多（国外企业） | 中等 |
| **Go 版本要求** | ≥1.18 | ≥1.18 | ≥1.18 |
| **Swagger 集成** | swaggo/swag 成熟方案 | echo-swagger | fiber-swagger |

### 调研结论

| 推荐 | 理由 |
|:-----|:------|
| 🥇 **Gin** | 社区最大、中文资料最多、中间件生态最丰富、国内生产案例最多 |
| 🥈 Echo | 性能相近，结构更清晰，但社区和生态不如 Gin |
| 🥉 Fiber | 性能最高，但 API 风格偏 Node.js，国内社区较小 |

## 5. PostgreSQL 部署方案

| 方案 | 适用场景 | 优势 | 劣势 |
|:-----|:---------|:-----|:------|
| **Docker 容器部署** | MVP / 开发环境 | 部署简单、环境一致、易于迁移 | 性能略低于裸机，需管理数据持久化 |
| **云托管 RDS** | 生产环境 | 自动备份、高可用、运维成本低 | 成本较高（¥200+/月） |
| **裸机部署** | 高性能需求 | 最高性能、完全控制 | 运维成本高 |

### 调研结论

| 阶段 | 方案 | 原因 |
|:-----|:-----|:------|
| MVP | **Docker 部署** (postgres:15-alpine) | 与 Docker Compose 统一管理，数据持久化到 volume |
| 生产 | **阿里云 RDS PostgreSQL** | 自动备份、监控告警、一键扩缩容 |

**Docker 部署配置示例**：
```yaml
# docker-compose.yml
services:
  postgres:
    image: postgres:15-alpine
    volumes:
      - pgdata:/var/lib/postgresql/data
    environment:
      POSTGRES_DB: smart_learn
      POSTGRES_USER: app_user
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    ports:
      - "5432:5432"
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app_user -d smart_learn"]
      interval: 10s
      timeout: 5s
      retries: 5
    deploy:
      resources:
        limits:
          cpus: '2'
          memory: 2G
```

## 6. 缓存方案选型

| 维度 | Redis 7 | ValKey | Memcached | 本地缓存 |
|:-----|:--------|:-------|:----------|:---------|
| **类型** | 内存 KV 数据库 | Redis 兼容 KV | 纯内存 KV | 进程内缓存 |
| **数据结构** | 丰富（String/Hash/List/Set/ZSet/Bitmap）| 丰富（同 Redis）| 简单（String）| 简单 |
| **持久化** | RDB/AOF | ✅ | ❌ | ❌ |
| **过期策略** | 多种（LRU/LFU/TTL）| ✅ | LRU | TTL |
| **集群模式** | 主从/哨兵/Cluster | 同 Redis | 一致性哈希 | ❌ |
| **Go 客户端** | go-redis / redigo | valkey-go | gomemcache | 原生 |
| **性能 (GET/s)** | ~100K+ | ~100K+ | ~120K | ~500K+ |
| **内存效率** | 高 | 高 | 极高 | 极高 |
| **运维复杂度** | 低 | 低 | 低 | 无 |

### 调研结论

| 推荐 | 使用场景 | 原因 |
|:-----|:---------|:------|
| 🥇 **Redis 7** | 主缓存方案 | 数据结构丰富（支持排行榜、计数器、消息队列）、持久化可选、Go 生态成熟 |
| 🥈 **本地缓存** (go-cache) | 热点数据缓存 | 无网络开销，适合高频读取的静态数据（如知识点树） |

**缓存策略**：

| 缓存对象 | 方案 | TTL | 说明 |
|:---------|:-----|:----|:------|
| 用户信息 | Redis | 30min | 存储用户基础信息 |
| 知识图谱 | Redis + 本地缓存 | 1h | 相对静态，本地缓存兜底 |
| 推荐题目结果 | Redis | 1h | LLM 推荐结果缓存 |
| 学习报告 | Redis | 10min | 报告生成后缓存，减少重复计算 |
| 题目详情 | Redis | 24h | 题目内容相对稳定 |
| 学习计划 | Redis | 实时 | 当天计划，频繁读写 |

## 8. 日志与监控方案

### 8.1 日志方案

| 维度 | 方案对比 | 推荐 |
|:-----|:---------|:-----|
| **日志收集** | ELK / Loki + Promtail / 阿里云 SLS | **Loki + Promtail**（轻量、与 Prometheus 生态集成）|
| **日志存储** | Elasticsearch / Loki / 文件 | **Loki**（按量压缩存储，成本低）|
| **日志查询** | Kibana / Grafana / 阿里云 SLS | **Grafana**（统一监控与日志查询）|
| **Go 日志库** | zap / logrus / zerolog | **zap**（性能最高，结构化日志）|

**日志分级**：

| 级别 | 使用场景 | 存储 |
|:-----|:---------|:-----|
| ERROR | 系统异常、数据库错误、LLM 调用失败 | 永久存储 |
| WARN | 请求超时、降级触发、限流告警 | 30 天 |
| INFO | 用户操作日志、请求记录 | 7 天 |
| DEBUG | 开发调试信息 | 不存储（开发环境）|

### 8.2 监控方案

| 维度 | 方案 | 指标 |
|:-----|:------|:------|
| **应用监控** | Prometheus + Grafana | QPS、延迟 P50/P95/P99、错误率 |
| **业务监控** | 自定义指标 | 用户活跃数、练习提交量、AI 调用次数 |
| **数据库监控** | pg_stat_statements + Grafana | 慢查询、连接数、缓存命中率 |
| **服务器监控** | node_exporter + Grafana | CPU、内存、磁盘、网络 |
| **告警** | Alertmanager | 钉钉/飞书告警通知 |

### 8.3 调研结论

| 推荐方案 | 理由 |
|:---------|:------|
| **日志**：zap + Loki + Grafana | 轻量级、资源占用低、与 Go 生态高度契合 |
| **监控**：Prometheus + Grafana + Alertmanager | 业界标准方案，开源免费，生态全面 |
| **告警**：飞书 Webhook | 公子使用飞书，直接集成 |
