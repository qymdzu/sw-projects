智能错题熔断与知识融通系统 —— 融合版功能描述
1. 核心引擎：多周期“熔断”与自适应“举一反三”
这是你流程的核心骨架，我们把AI驱动的“举一反三”直接嵌入到每个裁决环节中。

每日收集池 (Inbox)

所有新错题自动进入“本周错题池”，状态为“待周测”。

每周“熔断”挑战 (周测)

触发与组卷：周末自动从“本周错题池”抽题，生成《第X周错题歼灭战》。

智能裁决：

裁决为“对”：标记为“通过周测”，移入“月观察列表”。

裁决为“错”：触发自适应举一反三。AI不只是让这道题下周重练，而是当场生成3道变式题，核心知识点不变但变换数字、情景或提问方式，加入到下周的错题池里一起重新排队。这道原题的状态则被重置为“待周测”，下周继续“练”。

每月“巩固”归档 (月测)

触发与组卷：月末从“月观察列表”中抽题，进行更高难度的变式抽查。

深度裁决：

裁决为“对”：这道题和它的变式兄弟们被集体打上“已归档”标签，进入学期总结库。

裁决为“错”：这是“假性掌握”。AI会进行知识溯源，不仅把这道题打回“本周错题池”，还会从关联的前序知识点中，选出2-3道更基础的补强题，一起打包丢回去，确保地基先打牢。

学期“综合”总结

调取所有“已归档”错题及其变式题，生成专属《学期知识弱点回顾手册》。

2. AI智慧大脑：知识点关联与融会贯通
智能打标与教材关联

每道错题入库时，AI自动完成：知识点标签化 (如小学数学/分数/异分母加减法)、错误类型归类 (计算错、概念错等) 和 教材章节绑定，形成 “错题-知识点-教材章节” 的知识图谱。

顽固点干预与AI私教

当一个知识点下的错题反复在“周测-月测”中循环，触发干预。系统调用大模型，结合教材数据，自动生成这个知识点的讲解卡片，内容包括：核心定义、公式、经典例题和易错点辨析。推送到平板上，让孩子先学后练。

3. 可视化学情与知识图谱
这是让你和孩子的努力“看得见”的核心，所有数据动态更新。

知识彩虹图

直观展示孩子整个学科的知识图谱。每个知识点用颜色表示掌握程度：

红色 (未掌握)：有错题被困在周测循环里。

黄色 (不稳定)：错题已通过周测，正在月观察期。

绿色 (已掌握)：本月所有错题已通过月测归档。

交互：点击任何知识点，都能看到其关联的所有错题、当前状态和变式题训练记录。

错题生命周期地图

以时间轴或卡片流形式，追踪每道错题的“旅程”：从“本周待练” → “变式题挑战中” → “月测通过” → “已归档”。让孩子充满成就感。

多维学情报告

自动生成：按周、月、学期输出图文报告。不只报告消灭了多少道错题，而是展示知识点的掌握进展。

弱点热力图：清晰展示哪个章节是“重灾区”，方便制定后续学习计划。

## 4. 漏题模块（公子 2026-06-06 补充）

**漏题 ≠ 错题**：
- 错题：做过但做错
- 漏题：完全没做出来/没掌握（可能根本没做过、可能跳过了、可能看了不会做）

### 漏题录入

- **拍照**：与错题共用拍照模块，标注为"漏题"类型
- **视频**：核心录入方式（与错题不同）—— 拍摄孩子**读题/思考/卡壳/跳过**的过程视频
  - 视频内容：孩子读题 → 卡在哪里 → 跳到下一题 / 直接空着 / 蒙答案
  - 时长：单题 5-30 秒为主
  - AI 分析：调云视频理解 API（暂定 OpenAI Whisper 转写 + DeepSeek 推理），自动判断：
    - 是否读懂题意（语义理解）
    - 卡壳的具体环节（计算/概念/审题/书写）
    - 漏题归因：不会做 / 跳题 / 审题错 / 知识点缺失

### 漏题池与错题池分离

- "本周漏题池" 独立于"本周错题池"
- 周测/月测各自独立调度
- 漏题通过周测后 → "月观察" → 月测 → 归档（与错题同样流程）

### 漏题与错题关联

- 同一知识点的"漏题"+"错题"在知识图谱中**强关联**（都打红）
- AI 私教讲解时优先处理"漏题"（比错题更严重）
- 学期报告里漏题数 = 独立指标

## 5. 移动端核心功能（公子 2026-06-06 强调）

**录入 = 移动端唯一入口**（学生模块 + 大人模块统一入口，按用户分工作空间）：
- 错题录入：**拍照**（单题 1-2 张照片）
- 漏题录入：**拍照**（单题 1-2 张照片，标注"漏题"）
- 大人读书笔记录入：**拍照**（段落/书页，可多张）
- 视频模块**暂不开发**（学生/大人都不用视频）
- 照片本地缓存 + 断网可暂存
- 联网后批量上传云端 AI 处理

**拍摄体验**：
- iPad/iPhone 调用系统相机 API
- 拍摄后**圈画**（手指在屏幕上圈出题目的关键区域/数字/选项）
- 提交时自动调 OCR API

**"去笔墨痕迹"处理**（学生模块核心需求）：
- 学生拍作业题：照片含**题目原文** + **学生自己的笔迹/勾画/涂抹/草稿**
- AI 必须在 OCR 前**去掉笔迹**，只留**纯净题目**
- 这是学生模块 OCR 的关键技术点（大人读书笔记不需要此步骤）

**离线模式**：
- 无网络时可继续拍照，本地 SQLite 存元数据
- 网络恢复后批量上传 + AI 处理

## 6. 多用户模块（公子 2026-06-06 补充）

**软件面向多用户**，不仅是学生。

### 用户类型

| 用户类型 | 工作空间 | 录入方式 | AI 任务 |
|:-----|:-----|:-----|:-----|
| **学生** | 错题/漏题工作空间 | 拍照（去笔迹） | OCR + 变式题 + 知识讲解 |
| **大人** | 读书笔记工作空间 | 拍照（段落/书页） | 摘要提取 + 关键信息存证 + 读书笔记生成 |

### 工作空间独立性

- 学生 vs 大人 = **完全独立的工作空间**
- 数据库表独立（user_id 隔离）
- AI 处理任务独立调度
- 可视化界面独立
- **数据绝不串联**（不会把大人的读书笔记跟儿子的错题混一起）

### 用户切换

- iPad/iPhone app 启动时**选用户身份**（学生/大人）
- iOS App 本地存当前用户 ID（SQLite）
- 同一台设备可被多用户共用（家里多人用一台 iPad）
- 后续可加密码/人脸识别保护隐私（v0.2 考虑）

### 大人模块子功能

1. **拍照录入**：拍书/文档/段落（可单张或多张一组）
2. **核心摘要提取**：AI 自动从图片提取文字 + 总结核心要点
3. **关键信息存证**：AI 把核心信息**以照片/截图形式保留**（不是只存文字）
4. **读书笔记生成**：AI 汇总多次拍的照片，输出结构化读书笔记
### 笔记导出：PDF / Markdown / 飞书云文档

## 7. OCR 抽象层与可扩展性（公子 2026-06-06 强调）

**核心要求**：OCR 服务必须**可插拔、可热切换**，不绑定单一服务。

### 设计原则

- **不直接调用具体 OCR API** —— 业务层只调用 `OCRProvider` 接口
- **OCR Provider = 独立 Dart class**（如 `BaiduOCRProvider` / `MathpixOCRProvider` / `AppleVisionOCRProvider`）
- **路由策略** = 业务层根据"题型"或"用户配置"动态选择 Provider

### OCR Provider 接口标准

```dart
abstract class OCRProvider {
  String get name;             // "baidu_edu" / "mathpix" / "apple_vision"
  bool supports(String questionType);  // 是否支持该题型

  Future<OCRResult> recognize({
    required File imageFile,
    required bool removeHandwriting,  // 是否去笔迹
    Map<String, dynamic>? options,
  });
}
```

### 路由策略

| 维度 | 默认 | 可扩展 |
|:-----|:-----|:-----|
| **全局默认** | 百度云教育版（去笔迹）| 用户可改 |
| **按题型路由** | 全部用百度 | 数学题用 Mathpix / 语文题用百度 / 印刷体用 Apple Vision |
| **按用户配置** | 单一 provider | 用户可加多个 provider + 优先级 |

### 路由配置示例

```yaml
# 用户级 OCR 配置（存在 SQLite）
ocr_routing:
  default: baidu_edu
  rules:
    - when: { question_type: "math" }
      use: mathpix        # 数学题走 Mathpix（公式识别准）
    - when: { question_type: "chinese" }
      use: baidu_edu      # 语文题走百度（中文强）
    - when: { has_handwriting: false }  # 印刷体
      use: apple_vision   # 走 iOS 原生（免费、本地）
```

### 扩展性承诺

- 加新 OCR 服务 = 新建一个 `OCRProvider` 子类 + 注册到路由表，**不改业务逻辑**
- 未来可能加的服务：腾讯云 OCR、阿里通义 VL、OpenAI GPT-4V、Google Vision
- 抽象层**不绑死**任何云服务商的 SDK 调用方式

### 抽象层 v0.1 实现计划

- 先实现 `OCRProvider` 接口 + 1 个实现（百度云）
- 路由表用 YAML 配置文件
- v0.2 实现 Mathpix / Apple Vision
- v0.3+ 跑通"按题型自动切换"
